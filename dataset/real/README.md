# dataset/real/ —— 授权真实照片（不入库）

## 这个目录是干嘛的

`dataset/dev/` 和 `dataset/lock/` 里的 43 张图**全是程序画的**，有三个绕不过去的偏差：

- **没有拍摄角度**（全是正视，无倾斜/透视）
- **文字过于清晰**（无运动模糊、无低光噪点、无纸张褶皱）
- **不含人脸**（无合规来源）

所以"召回 100%"只是**合成集上的表现**。真实照片能验证：换到手机拍的、有反光有角度的图，检测器还准不准。

## 为什么单独放这里

**这个目录被 `.gitignore` 排除**，原因不是怕占体积，是隐私：

1. **进 git 就永久留在历史里**——即使后来删了文件，`git log` 里还能翻出来
2. **会进交付包**——`tools/make_handoff.py` 用 `git ls-files` 取材，入库的东西会跟着发给 A 和 B
3. 真实照片可能带**真实**的手机号、二维码，那是别人的隐私

只有 `README.md` 和 `manifest.example.csv` 两个文件入库（作为说明），照片本身**永远不进版本控制**。

## 该放什么、不该放什么

| ✅ 可以 | ❌ 不要 |
|---|---|
| 自己拍的、内容**虚构**的单据（号码是编的） | 真实的快递单、发票、证件 |
| 自己的正脸照（仅限本人，且书面同意） | 别人的照片，哪怕"他说可以" |
| 屏幕截图（内容是假数据） | 含真实聊天记录/联系人的截图 |

**核心原则**：图里出现的号码、姓名、二维码，**必须是编的**。你要测的是"检测器能不能认出它长得像敏感信息"，不是"能不能读到真的隐私"。

## 怎么用

1. 照片放这个目录，命名 `real-001.jpg` 起
2. 在 `manifest.csv` 里登记（模板见 `manifest.example.csv`）
3. 跑检查：`python tools/real_samples_check.py`
4. 结果只用于**报告里单独一节**，不和合成集混算平均值

**不和 dev 混算**是硬规矩：合成 43 张 + 真实 10 张算平均召回，等于用干净数据稀释真实难度，最后得出一个谁都不信的中间值。要分开报。

## 用完怎么办

照片可以留在本地（不影响仓库），也可以删。删之前跑一次 `python tools/real_samples_check.py --seal` 把哈希记下来，
报告里引用哈希而不是图片本身。

## 授权书

每张照片的来源都要能说清。`manifest.csv` 里的 `consent` 列填授权方式：

- `self` —— 本人拍摄、本人同意
- `team-written` —— 团队成员书面同意（要留一份签字的纸）
- `synthetic-photo` —— 屏幕翻拍合成图（介于两者之间，最安全）

**没有 `consent` 的照片不要用。** 答辩被问"这张图哪来的"答不上来，比指标低十分严重。

## 首批素材（2026-11-07）

**已入库 14 张，全部内容虚构**：9 张屏幕翻拍（渲染单据）+ 5 张手写纸面。
清单见 `manifest.csv`（同样不入库）。刻意埋了三类难负例：掩码手机号、座机号、掩码证件号。

实测结果与结论在 **`docs/真实照片首测_2026-11-07.md`**，一句话概括：

```
手机号 11/13（84.6%）  身份证 2/3（66.7%）  二维码 0/5  一维条码 0/3  误报 0
对照：同一检测器在合成 dev 集上是 52/52、召回/精确 100%
```

**二维码 0/5 的原因是屏幕摩尔纹**，不是算法缺陷——`cv2` 能定位到四角，
但模块被条纹破坏到无法采样，透视矫正 + 二值化也救不回。**纸张实拍的码还没测**，
所以报告里不能写"二维码检出不可用"，只能写"屏幕翻拍场景不可解"。

**下一步若要补拍**：优先拍**纸面**的二维码与条码（能解），以及更多手写体
（手写是当前误读的主要来源）。
