## 一、这个要求是怎么来的

| 项         | 内容                                                                                                                         |
| --------- | -------------------------------------------------------------------------------------------------------------------------- |
| 依据        | 《功能规格卡 v1.4》**§R-04 第二 OCR + 人工抽检**（第 1001–1005 行）                                                                         |
| 原文        | 「随机抽 **30 个已处理对象**，**两人独立**判断『是否还能读出』，记录一致率与分歧案例」                                                                          |
| 产出要求      | 「第二套 OCR 的交叉验证结果 + 30 个样本的人工判读一致率」，报告中两个结果都要给                                                                              |
| 排期        | S4（W15–W19），预算 2.5 人时（A 1.5 / C 1.0）                                                                                       |
| 验收方式      | 审计项 **R04-01**（负责人 B）：自动交叉率 ≥90%、原图正控 ≥80%，**且**存在 `manual-summary.json` 且状态为 `complete_two_independent_reviewers` 才判 PASS |
| 现状        | 自动部分已完成（同模型一致率、原图正控 29/30）；**人工判读 30 行全空**，所以审计停在 `PARTIAL`                                                                |
| 为什么必须两个真人 | 规格卡写的是「两人独立判断」。一人填两份等于伪造验收证据，比留空更糟                                                                                         |

**这 30 个对象从哪来**：从已处理（遮盖后）的 dev 样本里抽的 30 个敏感对象——
20 个手机号 + 10 个身份证。前 4 位/前 3 位与末 4 位保留可见，中间是星号（见第 4 列）。

---

## 二、怎么填（30 秒看懂）

打开随附的图片 **`R04_处理对象接触表_2026-11-15.png`**，图上有 30 个小格，编号 1–30，与下表序号一一对应。

| 你在格子里看到        | 第 5 列填         |
| -------------- | -------------- |
| 一片纯黑或灰，读不出任何数字 | `not_readable` |
| 还能读出号码（哪怕只有几位） | `readable`     |

- 只填第 5 列；第 1–4 列留着做对照
- 不要和另一位评审讨论，也不要看对方的表
- 拿不准时按「能读出就填 readable」从严处理

**预期**：30 行大概率全是 `not_readable`。如果你某行填了 `readable`，请在备注里写下能读出什么——
那是真问题（遮盖有遗漏），比"全黑"有价值得多。
