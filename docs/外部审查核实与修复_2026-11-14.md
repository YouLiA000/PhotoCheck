### 3. 旧 revision 与报告失效

主要结论属实。

- 新计划开始处理时，当前输出和报告先失效；
- 新结果成功后再写回；
- 服务端根据实际决定集合计算 revision，不再信任前端上传的数字；
- 前端收到结果后同步服务端返回的 `plan_revision`；
- 被替代的 `work/outputs/run-*` 目录会删除；
- 本地原始上传和输出增加 24 小时保留上限，服务启动时清理过期项。

### 4. K-02 无 ExifTool 降级

属实。原实现在找不到 ExifTool 时直接删除输出，与规格卡的 Pillow 降级不一致。

现在先尝试 ExifTool；不可用或扫描失败时，用 Pillow 重开文件并检查：

- PNG `eXIf / tEXt / zTXt / iTXt` 块；
- JPEG APP1 Exif/XMP、APP13 Photoshop、COM 和其他非白名单 APP 段；
- 允许新建 sRGB ICC，拒绝原始元数据段。

回归测试同时覆盖“编码器回退后真的塞入文本块必须失败”。

### 5. 离线扫描盲区

属实。原脚本只扫 `photocheck/`。

现在覆盖 `app/ audit/ contract/ eval/ photocheck/ scripts/ tools/ ui/`，只允许：

- 本地 HTTP 服务创建监听 socket；
- 构建脚本访问 `127.0.0.1` 健康检查；

任何外部主机、DNS、通用 outbound socket 调用都会失败。主入口安装 guard 后
执行 canary，证明拦截确实生效。`audit_offline.py --run-smoke` 实测静态通过，
端到端 3 个检测项并得到 `passed`。
