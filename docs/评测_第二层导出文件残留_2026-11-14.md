> 对应 B 的任务表第 1 项："eval 第二层仍为空表；虽然 43 图调跑过，但还没有整理进正式评测模板"。

> 这一版跑的是 **B 的 11-14 交付包**（`d0c45ea`），并且已经把第二层接进 `eval/`，
> 与第一层共用同一次运行的预测。

## 一、这一层在测什么

**不是**测"中间图上有没有盖住"，而是测**最终导出的那个文件**里还有没有东西：

| 检查面 | 判据 |
|---|---|
| 元数据 | 导出文件的 EXIF / XMP / IPTC / MakerNotes 是否为空 |
| 像素 | 逐区域复检（K-09）是否通过、有无残留 |
| 整图 | 全图重扫有无计划外检出（R-03） |

## 二、方法：不依赖被测实现

如果只用被测程序自己的结论，那测的是"它以为自己清干净了"，不是"真的干净了"。

所以流程是：

```
B 的 process() 跑完
  → 拿到 output_path
  → 用 ExifTool 独立读一遍（-EXIF:all -XMP:all -IPTC:all -MakerNotes:all）
  → 有字段就是残留，与 process 报告的 disposal_state 无关
```

**数据**：dev 43 张里的 38 张有效图（5 张 broken 不参与）。全部用 `solid`、全选处置。

## 四、一个会重复踩的坑：ICC profile 不是隐私残留

第一版统计报了 **38/38 有残留**，字段是 `CreateDate` 和 `Model`。

**是误报。** 这两个来自导出的 **ICC 色彩配置文件**：

```
[ICC-header]  Profile Date Time : 2026:11:14 13:26:00
[ICC_Profile] Device Model      : （空）
```

标准 sRGB ICC profile 自带 `Device Model` / `ProfileDateTime` 等字段，
它们是**色彩管理的固有字段**，不含任何拍摄信息。

**判据修正**：只查 `EXIF:all / XMP:all / IPTC:all / MakerNotes:all`，
**排除 `ICC_Profile` / `JFIF` / `File` / `System` 组**。

用宽判据（只要 key 里含 `Model` 就算）会把 `Device Model`、`ProfileDescription` 全扫进来。
这条已写进 `AGENTS.md` 的坑列表。

## 五、结论与局限

**结论**：第二层（导出文件残留）在 dev 38 张上**全绿**——元数据 0 残留、复检 0 失败、整图 0 计划外。

**三条局限（写报告时必须交代）**：

1. **只测了 `solid`**。`blur` / `mosaic` 不是"必过"，尤其 blur 在短边 1/4 核时会被 OCR 探针读出来。
   B 已把核提到 3/4，但那是他 11-13 之后改的，本表跑的是 11-14 包，**blur 需要单独一批**。
2. **合成图无真实 EXIF 多样性**。dev 里只有 8 张带 EXIF，且都是程序写的固定值
   （GPS/时间/机型/软件）。真实手机照片的 MakerNotes 结构复杂得多，清不干净的风险更高。
3. **没有"过度脱敏"的判据**。这一层只管"有没有漏"，不管"有没有盖过头"——
   那是第三层，需要人工判读。

## 六、复现

```bash
# 1. 解压 B 的交付包
unzip PhotoCheck_App_<时间戳>.zip -d D://tmp//pc

# 2. 跑第二层，同时导出第一层预测
python tools/run_layer2.py --pkg D://tmp//pc//PhotoCheck_App \
    --predictions D://tmp//pred --layer2-json D://tmp//layer2.json

# 3. 把一、二层合成一份标准结果（EV-02 只认同一次运行）
python eval/eval.py --set dev --pred-dir D://tmp//pred --layer2 D://tmp//layer2.json

# 想看 blur 的表现（那一档不是"必过"）
python tools/run_layer2.py --pkg ... --method blur --out results/layer2_blur
```

退出码：`0` = 元数据 0 残留且无异常；`1` = 有残留或跑挂了。
