# A / B 模块的数据需求与接口约定（C 视角整理）

> 日期：2026-11-07 ｜ 依据：`contract/schema/photocheck-v4.schema.json`、A 的 `core/detect/pipeline.py`、
> B 的 `photocheck/core/{ingest,pipeline}.py` 与 `contract/workflow.py`、`detectors/a_adapter.py`（全部读过源码，非转述）
> 用途：说清 **A 需要什么、产什么；B 需要什么、产什么；两者怎么接**。C 侧只做数据与评测，不实现检测也不做处置。

## 0. 一张图上的数据流

```
原始文件 ──[B: ingest_image]──> IngestedImage ──[A: analyze]──> AnalysisResult
             │ ①EXIF 方向矫正                    │ Detection[]（text/qr/face）
             │ ②meta 检测（K-02）               │
             ▼                                  ▼
        descriptor + meta 检测            B 合并两份 Detection
             │                                  │
             └──────────[B: build_redaction_plan]◄── 用户 Decision[]
                                │
                                ▼
                        RedactionPlan ──[B: process_and_export]──> 导出文件 + VerificationReport
                                                    │
                                                    └──[A: probe_region] 逐区域复检（K-09）
```

**一句话**：B 负责"把图变成可处理的规范图"，A 负责"在图上报出敏感对象"，B 再负责"擦掉 + 自证擦干净"。

## 1. A 模块

### 1.1 需要什么数据（输入）

| 项 | 类型 | 由谁提供 | 字段/约束 |
|---|---|---|---|
| `image` | 路径 `str` / `PIL.Image` / `ndarray` | **B（`ingest_image` 产出的工作图）** | **必须是已按 EXIF 方向矫正后的图**。若 A 自己读原图再矫正，与 B 的坐标会差一个转置，表现为"框全部偏移"——这是最难查的一类错 |
| `image_id` | `str \| None` | **B 传入** `ingested.descriptor["image_id"]` | 不传则取文件名。**必须与真值/C 的数据集一致**，否则评测时整批对不上（C 的 eval 会直接退出码 2） |
| `kinds` | `Sequence[str]` | 调用方 | 默认 `("text","qr","face")`。C 评基线时传 `("text","qr")`（meta 是 B 的活） |
| `cfg` | `DetectConfig \| None` | 可选 | 阈值集中在这里，不要散落 |
| `store` | `SecretStore \| None` | 可选 | 明文临时容器；不传则明文不留（也就无法人工抽检） |

**A 不需要也不应该要的东西**：原始 EXIF、原始文件名、用户 Decision、PII 历史。

### 1.2 产出什么（输出契约）

`analyze()` 返回 `AnalysisResult`，四个字段：

| 字段 | 类型 | 要求 |
|---|---|---|
| `image_descriptor` | `dict` | 契约 v4 `ImageDescriptor`：`contract_version="photocheck/v4"`、`record_type`、`image_id`、`width`、`height`、**`orientation="exif_transposed"`**、`coordinate_space="top_left_pixels"` |
| `detections` | `list[dict]` | 契约 v4 `Detection[]`，逐条见下表 |
| `warnings` | `list[str]` | 人可读；**检测器不可用必须出现在这里**（如 `face detection unavailable: ...`） |
| `timings_ms` | `dict[str, float]` | 分 kind 耗时，键为 `text` / `qr` / `face` |

**每一条 Detection 的字段**：

| 字段 | 约束 | 备注 |
|---|---|---|
| `id` | 全局唯一 | B 的 `build_redaction_plan` 用它把 Decision 配对回 Detection |
| `image_id` | 与 `image_descriptor.image_id` 一致 | 不一致会在 B 的跨记录校验里炸 |
| `kind` | `text` / `qr` / `face` / `meta` | **A 只产前三类**，`meta` 由 B 的 K-02 产 |
| `subtype` | 枚举内，且与 kind 匹配 | `face` 固定为 **`face_region`**（不是 `face`）；`text`: phone/idcard…；`qr`: qr_link/qr_wifi/qr_vcard/qr_wechat_pay/qr_unknown |
| `bbox` | `[x,y,w,h]` 整数，图像内 | **meta 必须为 `null`**；其余必须非空 |
| `detector_score` | `0..1` 或 `null` | **规则类不产生概率，但要保留上游 OCR 的置信度**（A 的实现取 `block.score`）。不要因为"手机号是规则匹配的"就把它抹成 `null`——那会丢掉一个有用的排序信号 |
| `evidence` | 枚举 | text→`ocr_rule`、qr→`qr_payload`、face→`face_box` |
| `risk` | 1/2/3 | 见 §1.3 |
| `details` | 按 kind 白名单 | text: `masked_preview` / `idcard_check`；qr: `decodable` + `safe_domain`/`safe_ssid`。**禁止 payload 原文** |

### 1.3 功能需求（对应规格卡）

| 卡 | 要求 | C 侧的验收依据 |
|---|---|---|
| K-03 | 文字检测；`T_ocr` ≤ 2023.6 ms（1686×1.2） | C 只记录，不判定 |
| K-04 | 手机号 `1[3-9]` + 9 位；身份证 18 位 + **MOD 11-2 三态**：pass→risk 3、fail→risk 2、**校验不通过也必须报** | dev 集有 10 条 idcard 正例（含 fail 类型） |
| K-05 | 二维码"解不出也必须标框" | dev/lock 共 15 条 qr 真值 |
| K-06 | qr 分类；`safe_domain` / `safe_ssid` 供界面显示 | 15 条真值已迁到 typed 字段 |
| K-07 | 人脸**只检测不识别**；不可用要如实报 | **C 无人脸样本，一律 `not_applicable`** |

### 1.4 接口约定

| 约定 | 内容 |
|---|---|
| **纯函数** | `analyze()` 不持有跨调用状态，同一输入可反复调用得到同结果 |
| **坐标空间** | 所有 bbox 都在 `top_left_pixels`（工作图，EXIF 已矫正） |
| **失败约定** | 单个检测器挂了 → 其它照跑，`warnings` 里写清原因，对应 kind 的计数为 0 且在 `RegionProbe.unavailable` 里列出 |
| **不猜不补** | 解不出的二维码报 `qr_unknown`（不丢框）；不给 `detector_score` 硬编一个数 |
| **`probe_region(image, bbox, cfg, kinds)`** | 返回 `RegionProbe{region, residual_text, residual_text_score_max, residual_qr_detected, residual_qr_decodable, residual_face, unavailable}`。**只给证据，不做 passed/failed 判定**——判定是 B 的 K-09 |

## 2. B 模块

### 2.1 需要什么数据（输入）

| 项 | 类型 | 由谁提供 | 约束 |
|---|---|---|---|
| 原始文件路径 | `str \| Path` | 用户 | JPEG/PNG；非图片或截断要有可读错误，不能静默 |
| A 的 `AnalysisResult` | `AEnvelope` | **A（经 `a_adapter.analyze_a` 校验）** | 校验不过直接拒，不得"降级成没检出" |
| 用户 `Decision[]` | `list[dict]` | 界面（C 的 UI 生产） | **每个非 meta Detection 恰好一条**，见 §3.2 |
| `manual_regions` | `list[dict]` | 界面（手动补框） | `finding_id=null`，默认 `solid`，二维码强制 `solid` |
| `revision` | `int` | 界面 | 用户改任一决定就 +1；旧 VerificationReport 立即失效 |
| ExifTool | 外部程序 | 环境 | **固定 13.61**（C 已统一） |

### 2.2 产出什么（输出契约）

**中间物 `IngestedImage`**：

| 字段 | 用途 |
|---|---|
| `descriptor` | 契约 v4 ImageDescriptor（orientation 也是 `exif_transposed`） |
| `image` | PIL 工作图（已矫正）；**A 的输入就是它** |
| `detections` | **仅 meta 类**（gps/datetime/device/serial）；A 不产这类 |
| `source_sha256` | 原图哈希，用于"不覆盖原图"的证明 |
| `source_format` | jpg/png，决定导出的编码方式 |
| `raw_metadata_ref` | 明文元数据的引用句柄，**不是明文本身** |

**最终物 `ProcessingResult`**：导出文件路径
+ `VerificationReport{disposal_state, checks[], residuals[]}`
+ **`full_file_recheck{}` 是 `ProcessingResult` 的独立字段**——不塞进 v4 `VerificationReport`，
  避免改动已冻结的 schema（B 的 2026-11-07 意见，C 已采纳）

### 2.3 功能需求

| 卡 | 要求 |
|---|---|
| K-01 | 载入 + EXIF 方向矫正 + 尺寸上限保护；坏图给可读错误 |
| K-02 | 元数据清除 + 像素重建导出；**不覆盖原图**；导出文件名不含原文件名 |
| K-08 | solid / blur / mosaic 三种处置；二维码只允许 solid |
| K-09 | 逐区域复检（b/c/d）+ 整图重检；`passed` 不等于"绝对安全" |
| K-15 | 打包与联调；ExifTool 是硬前置 |

### 2.4 接口约定

| 约定 | 内容 |
|---|---|
| `ingest_image(path, *, secret_store, exiftool_path, ...)` → `IngestedImage` | ExifTool 缺失应抛 `ImageIngestError`（**不是 skip**） |
| `build_redaction_plan(image, detections, decisions, *, revision, manual_regions, method_by_finding)` → `dict` | 内部先 `validate_records`；Decision 与 Detection 不配对抛 `ContractError` |
| `process_and_export(ingested, plan, *, output_dir, detections, decisions, ..., run_full_recheck)` → `ProcessingResult` | 内部再校验一次全记录。**`run_full_recheck=True` 必须显式传**，默认 False 会跳过整图重检 |
| `analyze_a(image, image_id, **kw)` → `AEnvelope` | **适配层必须校验 A 的 envelope**，字段不符立刻拒 |

> ### ⚠ `run_full_recheck` 必须显式传 `True`
>
> 逐区域复检（K-09b/c/d）只探**计划遮盖区域**，框外残留完全看不见——曾经因此把一张
> 带框外误报的图判成 `passed`。
>
> 整图重检（`full_file_recheck`）才回答"这张图还有没有漏掉的敏感内容"。
> **C 的调用链一律显式传 `True`，不依赖默认值。**
>
> **给 B 的建议**：正式业务入口应改成**强制整图重检**——参数不给默认值（强制调用方决定），
> 或干脆内置、不提供关掉的开关。「默认关、记得传」这种设计，早晚会有人在某个分支上漏传。
> 这不是防御性编程，是因为漏传的后果是**用户带着残留导出了**，而报告上写着 `passed`。
| `probe_a_region(image, bbox, **kw)` → `dict` | 传**导出文件**或内存图；bbox 是工作图坐标 |

## 3. A ↔ B 的数据依赖与交互

### 3.1 时序上的四个硬约束

| # | 约束 | 违反的后果 |
|---|---|---|
| 1 | **B 先 `ingest_image`，A 后 `analyze`** | A 自己读原图会跳过 EXIF 矫正，与 B 的坐标差一次转置，框全偏 |
| 2 | **`image_id` 由 B 传给 A**（= `ingested.descriptor["image_id"]`） | C 的评测按 image_id 对齐，不一致 → 整批算漏检、指标 0 分却正常退出 |
| 3 | **A 的 `orientation` 与 B 的 `descriptor` 必须同值**（`exif_transposed`） | 一边 `as_stored` 一边 `exif_transposed`，真实旋转照片上坐标语义冲突 |
| 4 | **`probe_region` 的 bbox 与导出图尺寸一致** | 导出做了缩放/裁剪就会框错位置，复检结论失效 |

### 3.2 Decision 配对的硬约束

`build_redaction_plan` 里这段是硬校验：

```python
actionable_ids = {d["id"] for d in detections if d["kind"] != "meta"}
decided_ids = {dec["finding_id"] for dec in decisions}
if decided_ids != actionable_ids:
    raise ContractError("every non-metadata Detection requires exactly one Decision")
```

**含义**：A 多报一条 Detection，界面就必须多出一条 Decision，否则 B 直接抛错。
**推论**：A 的误报不只是"指标难看"，它会**卡住整条流程**——所以 BC-0009 那 7 条 qr 误报必须修。

### 3.3 复检时的往返

```
导出文件 ──[A: probe_region(bbox)]──> RegionProbe
                                          │  residual_text / detected / decodable / unavailable
                                          ▼
                                   [B: K-09 判定] → passed / failed / pending
```

**分工边界**：A 只回答"这个区域里还剩什么"，B 决定"这算不算通过"。A 不能返回 `passed`。

### 3.4 各自不产什么（避免重复实现）

| 数据类型 | 唯一生产者 | 另一方必须 |
|---|---|---|
| meta（gps/datetime/device/serial） | **B（K-02）** | A 不产 |
| text / qr / face | **A** | B 不自己检测（`probe_region` 除外） |
| Decision | **界面（C 的 UI）** | A/B 都不生成 |
| RedactionPlan | **B** | A 不碰 |
| 真值与评测 | **C** | A/B 都不改 |

## 4. C 在这条链上的位置

| C 提供 | 给谁 | 形式 |
|---|---|---|
| dev 40 张 / lock 23 张 + 契约 v4 真值 | A（评基线）、B（集成测试） | `dataset/{dev,lock}/`，真值随图生成 |

| C 消费 | 来自 | 形式 |
|---|---|---|

## 5. 需求清单（可逐条勾）

### A 侧

- [ ] `image` 参数接受 B 的 `IngestedImage.image`，不再自行读盘矫正
- [ ] `analysis.image_descriptor.orientation` 恒为 `exif_transposed`
- [ ] 每个 Detection 的 `id` 全局唯一、`image_id` 与 descriptor 一致
- [ ] 身份证三态：pass→risk 3，**fail→risk 2 且必须报**，日期非法→丢弃
- [ ] 二维码解不出时报 `qr_unknown`，且**不得把文字区报成码**
- [ ] qr 的 `details` 只给 `safe_domain` / `safe_ssid`，不给 payload
- [ ] 检测器不可用时写 `warnings`，`detector_status()` 如实返回
- [ ] `probe_region` 返回 `detected` / `decodable` 分开计数，不返回 verdict

### B 侧

- [ ] `ingest_image` 产出 `orientation="exif_transposed"` 的工作图，供 A 直接使用
- [ ] ExifTool 缺失抛错误而非 skip；版本固定 13.61
- [ ] `analyze_a` 校验 A 的 envelope，字段不符即拒（不降级成"没检出"）
- [ ] `build_redaction_plan` 的 Decision 配对错误信息可读（说明谁多了谁少了）
- [ ] `probe_region` 的 bbox 用工作图坐标，导出图尺寸与工作图一致
- [ ] 逐区域复检 + 整图重检都做；`passed` 文案只允许"本次计划中待处理区域未发现残留"
- [ ] 导出不覆盖原图、文件名不含原文件名

### 两者共同

- [ ] `contract_version` 恒为 `photocheck/v4`
- [ ] 不把明文（号码、payload、EXIF 原文）写进日志 / CSV / 异常消息
- [ ] 同一份输入重复调用，结果一致（无隐藏状态）
