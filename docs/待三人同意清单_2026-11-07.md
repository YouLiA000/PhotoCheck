### D-1｜mediapipe 版本 —— **已按 B 的方法执行并验证，不需表决**

**我 20:00 那版的结论是错的**：

> 「装 `mediapipe==0.10.14` 会把 numpy 1.26.4 拉到 2.4.6，两者不能共存」

**B 指出这是安装方式问题，不是版本冲突。** 按他的做法复现：

```bash
pip install "mediapipe==0.10.14" "numpy==1.26.4"   # 同时给 numpy 锁
# Would install jax-0.7.1 jaxlib-0.7.1 mediapipe-0.10.14 ml_dtypes-0.5.4 scipy opt_einsum
# numpy 不在列表里 —— 不动
```

实际装完：

```
numpy 1.26.4 | mediapipe 0.10.14 | solutions True | cv2 4.10.0 | rapidocr ok
detector_status() → {'ocr': 'ok', 'qr': 'ok', 'face': 'ok', 'qr_backend': 'pyzbar'}
```

**根因**：单独 `pip install mediapipe==0.10.14` 时，pip 把 `jax` 解析到最新 **0.10.2**，
而 0.10.2 要求 `numpy>=2` → numpy 被升级。**给了 `numpy==1.26.4` 的锁，pip 会回溯到 jax 0.7.1。**

**结论**：

| 项 | 值 | 合规 |
|---|---|---|
| `requirements.txt` | `mediapipe==0.10.14` + `numpy==1.26.4` | ✅ 同时满足规格卡 §0.3 的两行 |
| 安装方式 | **必须 `pip install -r requirements.txt`**，不能单独装 mediapipe | — |
| face | **可用**（`detector_status()['face'] == 'ok'`） | K-07 / K-09d 恢复 |

**给 B 的答复**：你说得对，我的回滚是安装方法造成的，不是版本不兼容。已改正并验证。

**改什么**

```diff
- mediapipe>=0.10,<0.11          # face detection
+ mediapipe==0.10.14             # 0.10.35 移除了 mediapipe.solutions，A 的代码直接 AttributeError
```

文件：`requirements.txt` 第 15 行。B 的 `requirements.txt` 要同步加这一行（他现在**根本没装**）。

**为什么必须改**

`>=0.10,<0.11` 装出来是 **0.10.35**，而那一版把 `mediapipe.solutions` 整个删了：

```

hasattr(mp, 'solutions') → False
top attrs: ['Image', 'ImageFormat', 'tasks']
```

A 的代码写 `mp.solutions.face_detection` → `AttributeError` → `face` 恒 `unavailable`。

**这不是版本号不匹配，是 API 被删了。** 表现：

- C 的 `check_env` 说 mediapipe 0.10.35 ✓（版本在区间内）
- B 的端到端日志说 `mediapipe failed (AttributeError: module 'mediapipe' has no attribute 'solutions')`

**影响谁**：C（requirements）、B（requirements 缺）、A（他的环境是 0.10.14，不受影响）

### E-2｜`finder_min_count` 取 3（P2）

**背景**：A 新增的未解码二维码门禁要求"检出 ≥3 个定位符"才保留候选框。

**取舍**：

| 取值 | 效果 |
|---|---|
| 3（现状） | 精确优先。C 的 7 条误报降到 0 |
| 2 | 能捡回"码被裁到只剩两个定位符"的情况，但放行面变大 |

**C 的立场：保持 3**。理由：

1. A 实测：真码裁到 55% / 65% / 75% 后，cv2 连候选四边形都不给，`min=1` 和 `min=3` 结果一样——**当前取值没有造成可测的漏检**。
2. C 的 dev + lock **没有任何"半张码"真值**。没有真值就放宽，是用假设换误报风险。
3. 如果真实照片里出现半张码，C 造样本进测评，那时候再改有依据。

**需要 A/B 确认**：同意保持 3。若任一方认为"半张码"在真实场景常见，说出场景，C 立刻补样本。

**建议补的原文**：

> 身份证规则的判定顺序：
> ① 18 位结构（末位可为 X）→ 否则不报；
> ② **生日段必须是真实存在的日历日期**（年月日合法）→ 否则不报；
> ③ 校验位决定三态：正确 = `pass`（risk 3），错误 = `fail`（risk 2，标注"可能录错"）。
>
> 理由：流水号可以构造成满足 MOD 11-2 校验位，仅凭校验位不能证明是身份证；
> 而一个日期段写错的号码，仍然可能是**录错一位的真实证件号**，所以要报、只降级。
