日期：2026-11-20

状态：建议作为功能规格卡 v1.4 正式改版文本，提交 A、C 做最终签字。技术结论与

## S-3：二维码风险

建议将以下四个 subtype 固定为 risk 3：

```text
qr_wechat_pay   = 3
qr_alipay       = 3
qr_wechat_group = 3
qr_geo          = 3
```

`qr_wechat_group` 与 `qr_geo` 取最坏情况下的保守上界。K-06 的说明文案必须使用
“可能入群查看历史”或“可能暴露位置”，不得写成每个码必然产生该后果。

冻结的 lock 集不重新封存。`image-lock-003`、`image-lock-015` 中定案前的历史
risk 2 继续保留；运行时展示按当前规则计算为 3。risk 不参与检测匹配，因此不改变
lock 的召回或精确率。

## S-6：身份证三态

建议把 K-04 的判定顺序固定为：

| 18 位结构 | 校验位 | 生日段 | 输出 |
|---|---|---|---|
| 不成立 | - | - | 不报 |
| 非身份证类 | `na` | - | 不属于身份证判定；保留 schema 的合法枚举 |
| 成立 | pass | 合法 | `idcard` / `pass` / risk 3 |
| 成立 | pass | 非法 | 不报，但保留并占用 18 位字符区间 |
| 成立 | fail | 任意 | `idcard` / `fail` / risk 2 |

被丢弃的 18 位候选不能再被手机号规则从中间切成 11 位。`image-lock-014` 保持
`idcard_check=fail` 正例，不修改、不重封。

## K-09：处置复检

建议将 K-09 固定为以下硬规则：

1. 每个 RedactionPlan item 必须有且恰有一条 VerificationCheck。
2. 缺 check 表示报告无效，校验器必须拒绝，不得生成最终结论。
3. 正常且无残留：check=`passed`，汇总=`passed`。
4. 明确没有执行：check=`not_run`，汇总=`failed`。
5. 已执行但检测器或方法不可用：check=`not_applicable`，汇总=`pending`。
6. 超时、异常、空响应、非法响应：check=`failed`，汇总=`failed`。
7. 手动区域只有结构检查：check=`not_applicable`，汇总=`pending`，不得表述为语义安全。
8. 二维码只要仍检测到码形或仍可解码，check=`failed`。
9. 空计划或全部 retain：汇总=`not_applicable`；retain 项只进入 residuals。

`method` 只表示复检手段，例如 `a_ocr_probe`、`a_qr_probe`、`a_face_probe`、
`solid_black_region`。异常原因不得编码进 `method`；具体异常类型只进入非契约诊断日志。

## K-03：纯 OCR 性能

建议把正式测法固定为：

1. 进程预热 1 次；每张图先作废 1 次，再至少测量 3 次。
2. 每张图先求图内中位数。
3. `median`、`p95`、`max` 都按“每图中位数”这一统计单位计算。
4. 同时报告图内极差中位数。
5. n < 30 时必须附 bootstrap 95% CI；不能改回按全部运行重采样。
6. 正式测量使用 AC 市电，并记录 CPU、电源状态、像素中位数和 OCR 字符数中位数。
7. 冷启动单独报告，不进入稳态统计。
8. 参考集固定为 `k03_ref_v1` 的 R1–R5；逐图 SHA-256、生成命令、seed、字体和字号必须可复现。
9. 每台机器在跑待测样本的同一次运行内先测 `k03_ref_v1` 的 R1–R5，得到
   `T_ref_local`；更换参考集、生成器或统计口径必须升版本并经三方同意。
10. p95 使用线性插值。`2690.2 ms` 保留为 B 验收机参考值，不参与跨机绝对判定。
    正式闸门为：

```text
median_of_image_medians / median(T_ref_local) <= 1.2
p95_of_image_medians    / p95(T_ref_local)    <= 1.5
max_of_image_medians    / max(T_ref_local)    >  2.0: 必须逐图解释
```

绝对毫秒数仍须报告并注明该机 `T_ref_local`，只用于横向对照。

`1686.3 ms` 仅保留为 `T_ocr_legacy` 预验收参考，不得冒充新参考集基线。K-03 只覆盖
纯 OCR；端到端检测、处置、复检和导出耗时由 B 单独报告 median/p95，首版不设硬闸。
