### B-6｜`requirements.txt` 里没有 mediapipe（**要加；你给的方法是对的，C 之前判断错了**）

**现象**：你的 requirements 只有 5 个包（Pillow / piexif / jsonschema / opencv-contrib-python / numpy），

**要加什么**：`mediapipe==0.10.14`（与 A 一致，也是唯一保留 `mp.solutions` 的可用版本）。

> ⚠ **本文档 20:00 版本写"别照抄 0.10.14，必须先 0.10.35"，那条是错的，已作废。**
> C 当时的判断基于一次失败尝试，但失败原因是**安装方式**，不是版本冲突。

**关键是安装方式**（B 在 `C对接答复` §3.2 指出的，C 已验证）：

```bash
pip install -r requirements.txt     # ← 整包装，让 numpy==1.26.4 的锁参与依赖解析
```

**不要单独 `pip install mediapipe==0.10.14`**：那样 pip 会把 `jax` 解析到最新 0.10.2，
而 0.10.2 要求 `numpy>=2`，numpy 被静默升到 2.4.6。

**给了 numpy 锁之后**，pip 会回溯到 jax 0.7.1：

```text
Would install jax-0.7.1 jaxlib-0.7.1 mediapipe-0.10.14 ml_dtypes-0.5.4 scipy opt_einsum
（numpy 不在列表里 —— 保持不变）
```

C 实测（2026-11-07 20:30）：

```
numpy 1.26.4 | mediapipe 0.10.14 | solutions True | cv2 4.10.0 | rapidocr ok
detector_status() → {'ocr': 'ok', 'qr': 'ok', 'face': 'ok', 'qr_backend': 'pyzbar'}
```

**所以你的 `requirements.txt` 现在就写 `mediapipe==0.10.14`，是对的**——
C 之前说"必须先 0.10.35、0.10.14 会拉 numpy 2"是判断错误，已改正并回滚了那条改动。

**这不是版本号不匹配，是 API 被删了。** C 自己的 requirements 也有同样问题，已列入待改（需三人同意）。

**验收**：全新 venv 装完，`python -c "import mediapipe as mp; print(hasattr(mp,'solutions'))"` → `True`。
