## 二、K-03 最终口径

### 2.1 测法与统计单位

1. 只对纯 OCR 稳态建立 K-03 闸门；冷启动单列。
2. 进程预热 1 次；每图先作废 1 次；随后至少运行 3 次。
3. 每张图先计算图内中位数。
4. 集合 `median`、`p95`、`max` 全部基于“每图中位数”：
   - `median_of_image_medians`
   - `p95_of_image_medians`
   - `max_of_image_medians`
   - `n_images`
5. 同时报告“图内极差中位数”，展示单图波动。
6. p95 的 n 小于 30 时，另报 bootstrap 95% CI；不得改回按全部运行计算。
7. 必须使用市电（AC）；电池结果只做诊断。
8. 必须报告 CPU、电源状态、像素中位数、OCR 字符数中位数。

## 五、K-09 最终口径

### 5.1 硬规则

1. 每个 RedactionPlan item 必须有且恰有一条 VerificationCheck。
2. 没有 check 是**报告无效**，不是 pending；校验器直接报错。
3. `not_run` 是明确“没执行”，disposal_state 判 failed。
4. `not_applicable` 是已执行检查但因环境/方法不可用，disposal_state 判 pending。
5. 检测器异常、超时、空响应、非法响应都判 failed，不能落入 pending。
6. 手动区域只有结构检查时判 pending，不得表述为语义安全。
7. 二维码只要仍检测到码形或仍可解码，判 failed。
8. 全部 retain 或空计划判 not_applicable；retain 只进 residuals。

### 5.2 状态映射

| 情形 | check status | 汇总 |
|---|---|---|
| 正常无残留 | passed | passed |
| 仍有残留 | failed | failed |
| 明确没执行 | not_run | failed |
| 环境不可用 | not_applicable | pending |
| 超时/异常/空/非法 | failed | failed |
| 手动仅结构检查 | not_applicable | pending |
| 项没有 check | 无效记录 | 不得生成最终报告 |

### 5.3 method 与错误原因

`method` 只写复检手段，例如：

```text
a_ocr_probe
a_qr_probe
a_face_probe
solid_black_region
```

`method` 不再承载 `error / timeout / invalid`。本轮不新增第五种 status，
也不把错误原因塞进 method：

- 环境不可用由 `not_applicable` 表达；
- 处理错误由 `failed` 表达；
- 具体异常类型只进入非契约诊断日志，不进 VerificationReport。

如后续确需错误细分，另立 v4 修订并加正式 `reason` 字段；不能靠猜 method 后缀。

### 5.4 实现要求

- B/C 两个 `compute_disposal_state` / `_derive_disposal_state` 同步：
  `not_run` 或缺失 -> failed，`not_applicable` -> pending。
- 校验器增加“每个计划项恰好一条 check”的跨记录测试。
- 增加 4 条回归：
  - environment unavailable + 显式 not_applicable -> pending；
  - plan item 无 check -> 报告无效；
  - not_run -> failed；
  - detector exception -> failed。
- 规格卡 §203 四态说明同步修订。
- 界面 pending 用灰/黄，不用成功色；旧报告不复用。
