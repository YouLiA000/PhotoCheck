## 3. C 接下来要改的：`RD-01` / `DET-01` 的检查口径

**你的诊断对**：C 的审计查 `src/` 目录，那是按 C 的仓库布局写的，而你的实现在 `photocheck/` 下。

### 改成什么

不再查目录名，改成**按你的 manifest 导入并检查可调用性**：

```python
# 伪代码
root = os.environ.get("PHOTOCHECK_REPO_ROOT")
if not root:
    return skip("未设置 PHOTOCHECK_REPO_ROOT，跳过跨仓库检查")   # SKIP，不是 FAIL
manifest = json.load(open(f"{root}/photocheck/interfaces.json"))
for name in ("analyze_a", "apply_redactions"):
    fn = getattr(importlib.import_module("photocheck"), name)
    assert callable(fn)
```

### 为什么是 SKIP 而不是 FAIL

原来的 `FAIL` 表达的是「实现不存在」；但实际是「**C 的仓库里没有这份实现**」，实现好好地在你的仓库里。
把"没条件检查"判成"检查不通过"，会让闸门永远红，最后大家都学会了忽略它——那闸门就废了。

**SKIP 是诚实的**：报告里会写清"未设置 `PHOTOCHECK_REPO_ROOT`，跨仓库检查未执行"。
