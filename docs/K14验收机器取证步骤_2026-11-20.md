## 二、操作步骤

### 1. 物理断网（不是"关代理"）

- [ ] 拔掉网线 / 关闭 Wi-Fi 硬件开关
- [ ] 确认没有 USB 网卡、手机热点共享
- [ ] 截图 1：`设置 → 网络和 Internet` 显示「无 Internet」

### 2. 确认真的不通

```powershell
ping 8.8.8.8
ping www.baidu.com
```

- [ ] 两条都超时/无法解析
- [ ] 截图 2：两条命令的输出

### 3. 跑取证脚本

```powershell
powershell -ExecutionPolicy Bypass `
  -File scripts\capture_offline_evidence.ps1 `
  -Python .venv\Scripts\python.exe
```

- [ ] 退出码为 `0`
- [ ] `docs/evidence/<时间戳>/` 下生成了 `network-summary.json`
- [ ] 打开发 JSON，确认网卡状态与联网测试字段均为"失败/离线"

### 4. 防火墙证据

- [ ] 截图 3：`wf.msc` → 防火墙状态（域/专用/公用三栏均"启用"）
- [ ] 截图 4：入站规则列表（显示默认阻止）
- [ ] 截图 5：出站规则列表（若有自定义阻断规则，一并截）
- [ ] 可选加分：`netsh advfirewall show allprofiles` 的文本输出存成 txt

### 5. 归档

把 5 张截图 + `network-summary.json` 放进 `docs/evidence/<同一时间戳>/`，
并写一份 `README.md` 说明：机器型号、断网方式、执行时间、执行人。

## 三、验收判据

| 项 | 判据 |
|---|---|
| 脚本退出码 | `0` |
| 联网测试 | 全部失败（不是"超时但能连"） |
| 冒烟 | `audit_offline --run-smoke` 通过 |
| 证据完整 | 5 张截图 + JSON + README 在同一目录 |
| 审计 | `EX-01`（K-14 离线可运行）保持 PASS |

## 四、两个注意

1. **提交前脱敏**：截图里可能出现内网 IP、主机名、WiFi 名称。放入仓库前把这些打码，或只提交 JSON 摘要 + 脱敏后的截图。
2. **只跑一次**：取证是"某台机器在某时刻"的事实记录，不要事后补拍——补拍的证据没有说服力，宁可说明"未在验收机器上执行"。
