## 二、K-03 性能口径最终方案

### 2.1 冻结方法

1. 测量预热后的纯 OCR 稳态；冷启动、OCR+QR、OCR+QR+人脸另列。
2. 进程预热 1 次；每张图先跑 1 次作废，从第 2 次开始计时。
3. 每张图至少跑 3 次，每图取中位数。
4. 正式验收至少 30 张有效图。
5. 必须报告 median、p95、max、n、CPU 型号、AC/电池、像素中位数、字符数中位数。
6. 电池模式结果不得进入正式 median / p95；只能作为单独诊断。
7. 冷启动单列，不参与稳态闸门。

### 2.2 固定参考集

A 指出的关键问题成立：冻结基线 `1686.3 ms` 的样本形状是
`0.36 MP / 91 字符`，与当前 dev 的 `1.4 MP / 63 字符`不同，不能直接比较。

最终采用：

- 建立一份固定的 K-03 参考集，建议 5 张，覆盖：
  - 0.36–0.56 MP 稀疏页；
  - 0.56 MP 密集页；
  - 1.4 MP 稀疏页；
  - 1.75 MP 稀疏页；
  - 1.75 MP 中等密度页。
- 参考集使用虚构内容，记录图片 SHA-256、像素、字符数中位数和生成命令。
- 冻结后不参与调参；更换参考图必须三人同意并升版本。
- 每份验收报告同时写“参考集 T_ocr”和“dev 验收集 median / p95”。

### 2.3 闸门

```text
median_dev ≤ 1.2 × T_ocr_ref
p95_dev    ≤ 1.5 × T_ocr_ref
max_dev    不设硬线，但必须报告；> 2 × T_ocr_ref 时逐图解释
```

本轮暂不把 p95 放宽到 `1.6×`。A 当前 `2521.2 / 2529.4 ms` 只余 8 ms，
说明旧样本口径和新统计方法还没有完成正式重测；应先按固定参考集重测，
不能因为擦线就提前放宽判据。

## 四、S-6 身份证最终方案

B 的 11-15“生日非法一律不报”版本撤回。采用 A/C 共同支持的 11-08 三态版：

| 18 位结构 | 校验位 | 生日段 | 输出 |
|---|---|---|---|
| 否 | — | — | 不报 |
| 是 | pass | 合法 | `idcard` / `idcard_check=pass` / risk 3 |
| 是 | pass | 非法 | 不生成 Detection，但占用字符区间 |
| 是 | fail | 任意 | `idcard` / `idcard_check=fail` / risk 2 |

关键规则：

1. 校验 fail 时，无论生日是否合法都必须报 risk 2；它可能是录错一位或两位的真实证件号。
2. 校验 pass + 生日非法时按构造流水号处理，不生成 idcard。
3. 被丢弃的 18 位候选仍必须占用字符区间，禁止手机号规则从中间切出 11 位造成新误报。
4. `image-lock-014` 保持 `idcard_check=fail` 正例，不回滚、不重新封存。
5. A 当前 `entities.py` 行为已符合，无需改检测代码；只更新规格文本、标注指南和回归测试名称。

## 五、K-09 状态机最终方案

采用阶段化判定。`not_run` 与 `not_applicable` 不再混用。

### 5.1 单项 status

| 情形 | status | 最终汇总 |
|---|---|---|
| 区域正常复检通过 | `passed` | 计入通过 |
| 区域仍有残留 | `failed` | failed |
| 计划区域没有 check | 缺失 | failed |
| 生成了报告但 check 为 `not_run` | `not_run` | failed |
| 检测器客观不可用，未执行检查 | `not_applicable` | pending |
| 检测器抛异常、超时、空响应、非法响应 | `failed` | failed，不能 pending |
| 手动区域只能做结构检查 | `not_applicable` | pending；不得解释为语义安全 |
| 二维码仍检测到码形或仍可解码 | `failed` | failed |

### 5.2 汇总规则

```text
任意 check failed 或存在缺失 check / not_run -> disposal_state=failed
否则存在 not_applicable                      -> disposal_state=pending
全部计划项 passed                            -> disposal_state=passed
计划为空                                     -> disposal_state=not_applicable
```

`retain` 仍只进入 residuals，不改变 disposal_state。

### 5.3 实现约定

1. 不新增第五种 check status；检测器错误统一映射为 `failed`。
2. 错误原因写进 method，如 `a_ocr_probe_error`、`a_qr_probe_timeout`、
   `a_face_probe_invalid`。
3. 环境不可用写 `a_ocr_unavailable` 等，status=`not_applicable`。
4. 手动结构检查写 `solid_black_region_structural_only`，status=`not_applicable`；
   只有后续增加真正语义验证后才可为 passed。
5. B 与 C 两个 `compute_disposal_state` / `_derive_disposal_state` 必须同步修改，
   缺失 check 和 `not_run` 都返回 failed。
6. 规格卡 §203 四态表同步修订，移除“not_run -> pending”。
7. 当前报告与旧报告不得复用；界面 pending 使用灰/黄，不能用成功色。
