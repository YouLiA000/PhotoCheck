# DR-004 K-03 / S-3 / S-6 / K-09 最终口径

- 日期：2026-11-15
- 状态：A、C 已于 2026-11-22 签字（K-03 的跨机判据由 `DR-006` 细化）
- 依据：`docs/AC回B口径表决整合与最终方案_v2_最终意见_2026-11-15.md`

## 结论

```text
K-03：中位数 + p95；以每图中位数为统计单位；AC + 固定参考集；
      正式判据使用同一次运行的本机参考 T_ref_local。
S-3 ：qr_wechat_pay / qr_alipay / qr_wechat_group / qr_geo 全部 risk 3。
S-6 ：pass + 正常生日 -> pass/risk 3；
      pass + 非法生日 -> 不报但占用字符区间；
      fail + 任意生日 -> fail/risk 2。
K-09：not_run、缺 check、检测器异常 -> failed；
      not_applicable -> pending；手动区域最多做结构检查，保持 pending。
```

## 理由

1. K-03 若按全部运行或逐图最大耗时计算，会被电源状态和单次抖动主导；固定每图中位数
   才能同时观察 median、p95 和长尾。
2. S-3 的 group / geo 按最坏情况取保守上界，避免把可能入群查看历史或定位具体地点的
   二维码降成普通联系信息。
3. S-6 的 fail 分支更可能是录错一两位的真实证件号，因此即使生日非法也必须报，采用
   risk 2；只有校验通过但生日非法时按构造流水号丢弃。
4. K-09 中“没有执行”和“环境不可用”必须分开。异常、超时或空响应是确认失败，不能
   长期停在 pending。

## Lock 历史值例外

`image-lock-003`、`image-lock-015` 封存时 `qr_wechat_pay=risk 2`，继续保留原字节，
不重封。该值属于 S-3 定案前的历史标签；运行时展示按当前规则重新计算为 3，
风险不参与检测匹配，因此不影响 lock 检测指标。

## 未采用方案

- K-03 不采用逐图最慢值，因为会把电池/后台负载误判为检测器退化。
- S-6 不采用“生日非法一律丢弃”，因为会漏遮真实证件中误录日期的号码。
- K-09 不把检测器异常归入 pending，否则损坏的检测器可以永久伪装成“尚未完成”。
