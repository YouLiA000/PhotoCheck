# DR-003 成品运行时技术栈追认

- 日期：2026-11-14
- 状态：**通过。A、C 已于 2026-11-22 书面签字**
- 关联：功能规格卡 v1.4 §0.3、§6；审查报告 P0-4

## 实现事实

可交付的本地成品 `app/` 当前使用 Python 标准库 `http.server` 启动仅绑定
`127.0.0.1` 的浏览器界面，并继续保留 C 侧 Gradio 原型 `ui/app.py` 作为
团队联调界面。运行时实际还使用以下已落地依赖：

| 项 | 规格卡原写法 | 当前实现 | 落地原因 |
|---|---|---|---|
| 界面 | Gradio | 标准库 HTTP + 原生 HTML/CSS/JS | 作为成品；Gradio 仅保留为团队内部联调界面，并移入开发依赖 |
| EXIF | piexif 为主、ExifTool 复核 | ExifTool 13.61 为独立复核主路径 | 覆盖 XMP/IPTC/MakerNote/PNG 文本块等 piexif 容易漏的容器 |
| OpenCV | opencv-python | opencv-contrib-python 4.10.0.84 | 避免两个发行包覆盖同一 `cv2`，并保留二维码能力 |
| 高斯模糊核 | 短边 1/4 | 短边 3/4 | 原核大小在实测中残留可读信息，二维码仍强制实心 |

## 签字条件与落地

1. **ExifTool 定位是运行时约定**：开发布局固定查找
   `tools/exiftool/exiftool.exe`，便携布局固定查找
   `runtime/exiftool/exiftool.exe`；`PHOTOCHECK_EXIFTOOL` 可显式覆盖。
   应用、离线脚本和环境自检统一调用
   `photocheck.core.metadata.find_bundled_exiftool()`，不再各写一份。
2. **Gradio 不属于成品运行时**：成品 `app/` 只用标准库 HTTP；
   `gradio==5.50.0` 只供 `ui/` 内部原型和开发测试，已从
   `requirements.txt` 移到 `requirements-dev.txt`。

## 结论

A、C 已接受当前实现及上述两条注记。成品发布包不再携带 Gradio；
内部联调环境通过 `requirements-dev.txt` 安装 Gradio。

## 理由

1. 成品需要在一台无网络的 Windows 机器上直接启动，标准库 HTTP 比完整 Gradio
   依赖树更小、更少启动耦合。
2. ExifTool 能独立检查 XMP、IPTC、MakerNote、PNG 文本块等 piexif 容易遗漏的
   容器字段，和 K-02 的“保存后独立复核”目标一致。
3. 只允许一个 OpenCV 发行包可避免两个 wheel 覆盖同一个 `cv2` 目录。
4. 实测 1/4 模糊核仍可保留可读信息，3/4 核才满足当前复检；二维码不受此项影响，
   始终强制 `solid`。
