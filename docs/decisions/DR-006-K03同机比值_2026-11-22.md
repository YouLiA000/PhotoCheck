# DR-006：K-03 使用同机参考集比值

- 日期：2026-11-22
- 状态：通过（A、C 均书面签字）
- 替代：`T_ocr_ref_v2 = 2690.2 ms` 作为跨机绝对耗时闸门的做法

## 结论

K-03 的正式性能判据改为同机、同次运行的参考集比值：

```text
median(待测) / median(T_ref_local) <= 1.2
p95(待测)    / p95(T_ref_local)    <= 1.5
max(待测)    / max(T_ref_local)    >  2.0 时必须逐图解释
```

`T_ref_local` 来自同一台机器、同一次运行中的 `k03_ref_v1` R1–R5。绝对
毫秒数仍须报告；B 验收机的 `2690.2 ms` 只作为横向参考，不再决定其他机器
是否通过。

## 理由

1. A 在同一代码、同一参考集、接电源的情况下测得跨机中位数差值 **1.68×**，
   已经超过 1.2× 闸门宽度。
2. 原绝对闸门会把 CPU、功耗墙、线程库差异判成检测器退化，测到的是机器，
   不是代码回归。
3. 同次运行的本机参考能抵消固定硬件差异，同时保留对待测集比例变化的敏感性。
4. `tools/k03_report.py evaluate_gates(reference_ms=...)` 已支持该口径；只改
   验收文字和 CLI 调用方式，不改算法。

## 未采用方案

- 不放宽到 1.5× / 1.8× 来迁就慢机器：阈值只是被调大，跨机问题仍然存在。
- 不继续使用固定 `2690.2 ms`：A 的 Ultra 7 实测中位 4529.6 ms、p95 4983.6 ms，
  但检测结果一致，说明会稳定误判。
- 不把绝对耗时完全删除：它仍是定位机器和版本差异的有用证据。
