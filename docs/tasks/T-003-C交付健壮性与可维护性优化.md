# T-003 · C 交付健壮性与可维护性优化

> 日期：2026-11-02 ｜ 状态：已完成 ｜ 不卡死计数：0

## 目标与冻结边界

在保留现有功能、公开函数签名、契约 v4、评测口径和接口 payload 的前提下，修复 C 侧已复现问题并完善运行说明。

- 不改：`docs/功能规格卡_v1.4.md`、共享 Schema、`docs/评测协议_v1.0.md`、lock 数据、A/B 模块。
- 输入：数据集真值、预测 JSON、上传图片、CSV、暂存文件、导出路径。
- 输出：原有记录/报告结构不变；异常输入应明确拒绝或显示可读错误；历史产物不被同秒任务覆盖。

## 已确认问题与修改范围

1. `ui/datasource.py` 声明先校验但实现未校验；`ui/app.py` 对坏图和同秒导出缺少防线。
2. `tools/privacy_scan.py` 重复实现掩码、真实数据目录被宽泛白名单覆盖、Git/读取失败会静默通过。
3. `dataset/tools/seal_lock.py` 缺少 `SEALED.json` 或其中哈希字段时仍可通过。
4. `dataset/tools/labels_csv.py` 非整数 bbox 被静默截断，clean 与对象行混写未拒绝。
5. `tools/smoke.py` 审计 JSON 解析失败时可能误通过；`tools/make_delivery.py` 对 dirty 包内容说明不准确。
6. `eval/eval.py` 同秒同提交的结果目录可能覆盖历史；README 目录树与实际不符。

## 方案与取舍

采用局部修复 + 回归测试，不做跨模块重写。候选“大规模统一抽象”虽能进一步去重，但变更半径大、容易改变接口，撤销条件是出现任何跨模块行为差异；本轮不采用。

失败处置：非法契约/CSV/预测输入拒绝；坏图在界面返回可读状态；隐私扫描自身失败返回 2；导出与评测通过唯一路径保留历史。无二阶协议效应，评测算法与报告字段均不变。

## 验证与回滚

- 新增边界测试先复现，再跑对应模块测试。
- 最终运行 `python tools/smoke.py`、隐私扫描、lock verify、语法编译和 git diff 检查。
- 所有修改均可通过 git  diff 审查并按文件回退；不删除现有资产，不重生成数据集。
- 中断恢复：已写测试但未改实现时，先确认预期失败，再继续对应最小修复。
