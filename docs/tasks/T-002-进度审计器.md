## 目标

```bash

```

1. **进度**：W4 / W6 / W8 三个闸门，各自还差哪几项，差的是谁的活。
2. **合规**：规格卡对每张卡的验收要求，哪些真达标、哪些只是"看起来做了"。

## 不做

- **不自动改代码**。审计只报告，修不修由人决定。
- **不假装能判断质量**。它能查「masking 模块在不在」，查不了「掩码够不够严」——
  后者只能靠人工抽检与 R-04 的 kappa。
- 不引入 pytest / rich 等新依赖。纯标准库，避免动 requirements。

## 加一条检查的做法

在 `audit/checks/` 任一模块里：

```python
@check("XX-01", "K-13", "检查项标题", level="P0", owner="C", gate=("W6",))
def my_check(ctx: Context) -> Result:
    n = len(list((ctx.dataset_dir / "lock" / "images").glob("*.jpg")))
    return ok(f"{n} 张") if n >= 20 else fail(f"{n}/20", "怎么办")
```

新模块要在 `audit/checks/__init__.py` 加一行 import —— 导入顺序决定报告里的卡片顺序。

## 过程记录

**首轮跑出 4 个 FAIL，其中 3 个是审计器自己的 bug**——这条最值得记：

| 误报 | 原因 | 修法 |
|---|---|---|
| DS-02 缺 5 份真值 | 按文件名猜「是不是坏图」，文件名是 `image-dev-027` 猜不出来 | 改读 `manifest.csv` 的 `template=broken` |
| DS-09 qr 配额 0/5 | 用 `subtype or kind` 统一取，而 qr 的 subtype 是 `qr_link` 这类 | 二维码按 kind 计，手机号/身份证按 subtype 计 |
| DS-10 图损坏 | 同 DS-02，把故意做坏的 54 字节图当成了损坏 | 跳过 broken |
| EN-02 rapidocr 未安装 | 包名叫 `rapidocr-onnxruntime`，不是 `rapidocr` | 用 pip 里的真实包名 |

**教训**：审计器的误报比漏报更伤——连续假警报会让人不再看报告。每条检查都要拿真实数据验证一次。

2. `ui/tests/test_ui.py:70` 断言 `row[5]`，但「位置」列是索引 6（`HEADERS` 明确定义）→ 1 个 failure。
