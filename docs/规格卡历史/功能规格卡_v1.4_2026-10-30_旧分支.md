# 照片分享前隐私体检与脱敏工具 · 规格卡 v1.4

> 项目代号：PhotoCheck ｜ 周期：2026-11 ~ 2027-04（24 周）｜ 团队：3 人（A / B / C）
> v1.4 修订：2026-10-30 ｜ 与《立项申请书 v4》对齐，修 8 项内部冲突（见第 6 节）
> v1.3 / v1.2 / v1.0 保留作历史

## 定位（v1.3 重写）

**面向中文校园场景的手机拍摄单据、证件与截图，构建虚构或授权样本的测试集与可复现评测协议，量化本地检测与脱敏方法的漏检、误报、处理后残留与过度脱敏；并以本地原型演示"检测 → 用户确认 → 脱敏 → 导出复检"闭环。**

三句话解释：

1. **产品是载体，评测是资产。** 结题时能独立成立的是「数据集 + 评测协议 + 有效性报告」，不是「功能很多的打码工具」。
2. **输入域收窄到"含有明确文字风险对象"的图像**：快递单、外卖小票、证件、门牌、含敏感信息的聊天截图。风景照、纯人像作为**扩展输入**，结果单独汇报，**不进入核心结论**。
3. **不做算法创新**。OCR、人脸、二维码都是成熟模型；本项目的贡献是**场景化评测 + 闭环工程**。

## 系统输入输出与隐私总定义（v1.4 新增）

**输入**：单张本地图片文件（jpg / png，heic 可选）。不接受目录批量、不接受网络地址、不接受剪贴板读取。

**输出（面向用户，只有两项）**

1. 一张脱敏副本：新文件，不覆盖原图，默认同目录 `<原名>_脱敏.jpg`。
2. 一段数行结论：发现项计数（按 subtype 分组）、用户处理与保留的选择、生成导出文件后的复检结果、能力边界说明。

**不输出**：原图副本、原图缩略图、完整文字或二维码原文、可被当概率解读的风险评分、“是否安全”的结论性判断、该不该发的社交建议。

**隐私总定义**：本项目只处理「位置或字段明确、可被自动检测、处理后可再次验证」的个人信息线索。
检测范围以 0.2 节 subtype 枚举为封闭边界，枚举之外的内容一概不作承诺。

### 0.2 共享契约 v3（三人共同遵守，改动需三人同意）

**Finding（所有检测器的统一返回）**

~~~json
{
  "id": "f-001",
  "kind": "meta | text | qr | face",
  "subtype": "见下方枚举",
  "bbox": [x, y, w, h],
  "score": 0.93,
  "evidence": "exif | ocr_rule | qr_payload | face_box",
  "text_ref": "仅内存持有，不落盘",
  "payload_ref": "仅内存持有，不落盘",
  "decodable": true,
  "idcard_check": "pass | fail | na",
  "risk": 1,
  "default_action": "hide",
  "selected": true,
  "action": "hide",
  "verify_status": "pass"
}
~~~

| 字段 | 规则 |
|---|---|
| bbox | **EXIF 方向矫正后的工作图坐标系**；kind=meta 时为 null |
| score | **仅用于排序与阈值过滤，不是校准后的风险概率**；报告中不得当概率解读 |
| evidence | **证据来源**，与风险严重程度是两个维度：exif=元数据直读；ocr_rule=OCR+规则；qr_payload=解码内容；face_box=检测框 |
| text_ref / payload_ref | **只允许存在于内存**；日志、历史、报告一律替换为掩码（如 138****0000） |
| decodable | 仅 qr 类有值；解不出为 false，**但仍必须给出 bbox** |
| idcard_check | 仅 idcard 有值：pass=校验位通过；fail=格式像但校验位不通过；na=不适用 |
| risk | 1 / 2 / 3 |
| selected | 用户是否勾选处理（默认 true） |
| action | hide / keep / skip |
| verify_status | not_checked / pass / fail / na |

**subtype 枚举（封闭列表，新增需三人同意）**

| kind | 允许值 |
|---|---|
| meta | gps, datetime, device, serial, thumbnail, software |
| text | phone, idcard, tracking, doorplate（基础）；address, studentid, bankcard, plate, email（后置） |
| qr | qr_wechat_card, qr_wechat_group, qr_wechat_pay, qr_alipay, qr_wifi, qr_vcard, qr_contact, qr_geo, qr_code, qr_link, qr_unknown |
| face | face_region |

**Verdict（复检器返回，两个结论分开）**

~~~json
{
  "disposal_ok": true,
  "known_residuals": [],
  "checks": [
    {"name": "exif", "scope": "selected", "ok": true,  "method": "exiftool + piexif"},
    {"name": "qr",   "scope": "selected", "ok": true,  "method": "pyzbar 重解码"},
    {"name": "ocr",  "scope": "selected", "ok": false, "method": "同 OCR 复跑"},
    {"name": "face", "scope": "selected", "ok": true,  "method": "mediapipe 复跑"}
  ],
  "disclosure": "所选处理项在本次复检中未发现残留（同一检测器，不代表内容绝对不可读，也不覆盖首次漏检）"
}
~~~

| 字段 | 含义 | 边界 |
|---|---|---|
| disposal_ok | **处置有效性**：只对 selected=true 判定，全部处理干净才 true；无处理后对象时为 null | 只回答"你勾选的有没有处理掉" |
| known_residuals | **已知保留项与复检异常**：来自 action=keep 与 verify_status=fail | **不包含首次检测就漏掉的对象**，不能叫"全图残余" |
| disclosure | 固定话术，必须带检测器限定语 | — |

> **v1.3 修正的语义漏洞**：v1.2 把这个字段叫 residual_risks 且描述成"全图残余提示"，但它只看得见已经检测到的对象，**看不见第一次就漏掉的**。改名 known_residuals 并明确边界；真正的"导出图全量重检"放在 R-03。

**界面文案强制规定**

- 只能显示「**所选处理项在本次复检中未发现残留**」
- 禁用「已经处理干净」「可以安全分享」「无隐私风险」

### 0.5 隐私与措辞红线（v1.2 新增，全部卡适用）

1. **原始 text / payload 永不落盘**。日志、历史、报告只存掩码。
2. **报告与面板默认只放脱敏后的图**，不放原图缩略图（原图缩略图 = 把隐私写进报告）。
3. **不做安全承诺**。禁用"已确保安全""可以放心分享""发给熟人问题不大"。只陈述事实：「未检出……（基于 X 检测器）」。
4. **不给社交建议**。工具不判断"该不该发""发给谁"，只列风险项，由用户决定。
5. **演示一律用虚构样本**（自打印假证、自写假单号、自己生成的二维码），不使用他人真实信息。
6. **不做人脸识别**，不引入 embedding 模型。

### K-04 敏感实体识别（基础 2 类）

| 项 | 内容 |
|---|---|
| 负责人 | **A** |
| 人日 | 2.5 |
| 周次 | W4–W5 |
| 依赖 | K-03 |

**输入**：文字块列表
**输出**：Finding 列表（kind=text）

**工具**

| 环节 | 工具 | 用法 |
|---|---|---|
| 正则 | Python re | 预编译 pattern |
| 身份证校验 | 自写约 15 行 | ISO 7064:1983 MOD 11-2，输出三态 |
| 上下文 | 自写 | 关键词在 box 附近 ±1 行 |
| 归一化 | 自写 | 全角转半角、去空格与连字符 |

**基础 2 类（v1.4 收缩，快递单号与门牌转后置）**

| # | 类型 | 规则 | 风险 |
|---|---|---|---|
| 1 | 手机号 | 1[3-9] + 9 位，两侧非数字，允许空格横线 | 2 |
| 2 | 身份证号 | 18 位（末位可 X）+ 校验位，**输出 idcard_check 三态** | pass=3 / fail=2 |
| 3 | 快递单号 | 顺丰 SF+12~13；通达系 12~14 位；京东 JD+11~13 | 2 |（后置，不进首版验收）
| 4 | 门牌 / 楼栋 | 数字 + 栋/幢/号/楼，可接单元室 | 3 |（后置，不进首版验收）

> **v1.3 修正**：v1.2 要求"篡改一位校验位必须不报"，这在真实场景会**漏掉打错一位的证件号**，而打错的号码同样泄露信息。改为三态：校验不通过仍提示，但降为 risk 2 并标注「格式像身份证，校验位未通过（可能录错）」。

**验收标准**

- [ ] 每类 ≥3 正样本、≥3 负样本
- [ ] 正样本召回 ≥ 80%；负样本误报 ≤ 2 处/张
- [ ] 校验位正确的样本 → idcard_check = pass（risk 3）
- [ ] 篡改一位的样本 → **不得标 pass**，但必须保留为 idcard_check = fail（risk 2）
- [ ] 手机号被拆成 138 0013 8000 时仍能识别

**降级**：手机号或身份证号召回不达标 → 先砍身份证号的上下文规则，只保正则 + 校验位三态。
> v1.4：与申请书「首版仅处理三类问题」对齐，首版文本只做手机号与身份证号；快递单号、门牌保留在枚举内但移入后置，不作为首版验收项。

**核心逻辑（两条独立结论）**

~~~text
对每个 selected=true 的 Finding：
    verify_status = 用独立代码路径重新检测该区域/该类型
    pass  -> 计入通过
    fail  -> disposal_ok = false，进 known_residuals

对 action=keep 的 Finding：
    -> 只进 known_residuals（提示），不参与 disposal_ok

若没有任何 selected=true 的 Finding：
    -> disposal_ok = null（不算失败）
~~~

**本卡能力边界（v1.3 明确写死）**

复检用的是与检测阶段**同一套模型**，所以它只能证明"同一检测器不再读出"，**不能**证明：

- 人类无法识别（可能仍然可读）
- 没有首次漏检（known_residuals 只看已检出对象）

这两件事分别由 **R-03（导出图重检）** 与 **R-04（第二 OCR + 人工抽检）** 回答。报告里必须这样写，不能越界表述。

**工具**

| 检查 | 工具 | 方法 |
|---|---|---|
| EXIF | ExifTool + piexif | 独立进程重新读文件 |
| 二维码 | pyzbar 重跑 | 对已遮区域解码 |
| 文字 | RapidOCR 重跑 | 对已遮区域 OCR |
| 人脸 | mediapipe 重跑 | 仅对 selected 的人脸区域 |
| 结构 | Pillow | 尺寸、可打开、非全黑 |

**验收标准**

**第三层 · 过度脱敏（v1.3 新增）**

- 非目标对象被误遮的数量
- 每图误遮对象数
- 人工记录"是否影响非敏感内容阅读"（是 / 否）

- 每个指标必须**同时给出 n**

## 2. 研究卡与演示卡（W9–W19）

> **v1.3 重排**：v1.2 的附加卡里，"扩类别 / 导出图 / 历史记录"全部后置。W9 以后的时间用于产出**可独立结题的评测资产**，而不是继续堆功能。

### R-01 标注指南与数据集 v0.1
**产出**：1 份指南（字段定义、分组规则、难度分级、正负样本配比）+ dataset v0.1（dev ≥40 / lock ≥20）
**工具**：Markdown 写指南；CSV 标注；Pillow 生成假样本
**验收**：新人照指南能在 1 小时内标注 5 张且与现有标注一致；lock 集封存并记录哈希。

### R-02 检测基线表 + 失败案例库
**产出**：第一层评测的四张表（召回 / 精确 / 误报 / 分 subtype）+ 按 subtype 归档的 badcase 目录
**工具**：eval.py；目录命名 subtype__reason
**失败原因分类**：OCR 未检出 / OCR 错字 / 规则未匹配 / 阈值误判 / 多目标重叠
**验收**：每张 badcase 都有原因标签；基线表能对比两次提交。

### R-03 导出图重检与误遮挑战实验
**产出**：对**最终导出文件**跑全量检测（而不是只看已选区域），统计"首次漏检在导出图里被发现的次数"
**工具**：同一检测管线对导出图跑全图重检，**漏检判定以人工标注真值为基准**；同管线重跑结果只用于发现「处理后可读性」问题，不用于自证漏检率
**验收**：能回答"漏检率大概是多少"（分母为人工标注对象数，不是已检出对象数）；能区分残留来自漏检 / 保留 / 遮挡失败。
> 这张卡补的正是 K-09 的边界：known_residuals 看不见第一次就漏掉的。

### R-04 第二 OCR + 人工抽检
**产出**：第二套 OCR 的交叉验证结果 + 30 个样本的人工判读一致率
**工具**：**Tesseract（pytesseract + chi_sim）**，不用 EasyOCR / PaddleOCR（要 torch，太重）
**方法**：随机抽 30 个已处理对象，两人独立判断"是否还能读出"，记录一致率与分歧案例
**验收**：报告里同时给出"同模型复检"和"独立 OCR + 人工"两个结果。

### R-05 复现包与结题材料
**产出**：固定版本 tag + requirements 哈希 + 一键脚本 + 演示录像 + 结题文档
**验收**：第三方按说明能在 30 分钟内复现出基线表。

### D-01 / D-02 演示增强
D-01 用 Gradio ImageSlider；D-02 遍历 selected 一键处理。两者都是低成本，放 P2。

### 后置（本周期不做）
自定义敏感词、模板扩到 8 类、二维码分类扩到 11 类、结论导出图片、历史记录。
> 这些是 v1.2 的 O-04 / O-05 / O-06 / O-08 / O-09。不做不是否定它们，而是**时间要花在能独立结题的资产上**。

## 5. 变更纪律

1. **冻结新功能，允许修缺陷**：W20 起打 tag v1.0-final，此后不得加功能；**任何 bug 修复必须附带一条回归测试**才能合并。
2. 换库需三人同意；subtype 枚举的增删同样需三人同意。
3. 每张卡完成必须写 3 行 README。
4. 每周日 20:00 同步 30 分钟：完成了什么 / 卡在哪 / 下周要什么。
5. **演示优先**：能完整演示 > 功能更多。
6. **样本必须授权**：任何样本加入数据集都必须单独取得授权并人工审核，**禁止把用户失败样本自动回流测试集**。
7. **lock 集纪律（v1.4 新增）**：lock 集只在 W14、W20 与答辩前各跑一次；任何模块的验收标准不得写「锁定集」——开发期验收一律用 dev 集，lock 集结果只用于最终报告，且跑完即记录，不再据此回改模型参数。
