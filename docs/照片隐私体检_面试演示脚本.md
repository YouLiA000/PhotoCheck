# 五分钟演示脚本 · PhotoCheck 照片隐私体检

> 用法：演示前照着「开场前 3 分钟」检查一遍，演示时按时间轴走。
> 括号里是**预期画面**，对不上就切到 §5 故障预案。

---

## 一、开场前 3 分钟（不在镜头里）

- [ ] 已解压到 `D:\PhotoCheck_App`（**不要放桌面或 Program Files**）
- [ ] 双击过 `启动.bat`，确认浏览器能打开、顶栏两个绿灯亮（引擎就绪 / ExifTool 就位）
- [ ] 提前点一次「通知单」示例，让模型加载完（**避免第一次演示等 5 秒**）
- [ ] 缩放 100%，窗口最大化；关掉微信等会弹窗的软件
- [ ] 准备一张自己的照片放在手边（§4 第 8 步要用）

---

## 二、时间轴

### 0:00–0:30　开场：它是什么

**操作**：指着已经打开的界面。

**口播**：

> 这是我做的一个小工具，叫照片隐私体检。
> 我们每天发快递单、发名片、发聊天截图，手机号就这么散出去了。
> 它做的事是：**把照片里的隐私线索找出来、擦干净，然后证明它真的擦干净了。**
> 全部在本机跑，不联网，不上传。

**要点**：说"证明擦干净了"时停半秒，这是全场最值钱的一句。

---

### 0:30–1:20　案例一：不是暴力匹配

**操作**：点左侧「通知单 · +86 三种写法」。

（图上是三种区号写法：`+86 177…`、`0086-1634…`、`+86185…`；三个都被框住，右下两个号没被框）

**口播**：

> 同一张纸上有三种写法：加号 86、0086 加短横、还有紧挨着写的。
> 三个都认出来了。**但你看下面还有两个号没被框**——
> 一个位数不够，一个前缀不合法。它不是"见到十一位数字就报"，
> 它算了校验位、也看前缀。

（右栏三个条目，都显示掩码，如 `177****4805`）

**要点**：主动指出"没报的"，比只讲"报出来的"有说服力。

---

### 1:20–2:00　案例二：一张图两个码

**操作**：点「名片 · 一图两码」。

（图上两个二维码 + 一个手机号，三个框；右栏三条：名片码 risk 3、手机号 risk 2、Wi-Fi 码 risk 3）

**口播**：

> 这是名片，上面两个二维码。很多实现只能解出第一个，
> 因为底层接口返回的是个"多值"，写错一行就只拿到一个。
> 这里是两个都出来，而且**解出内容之后才判类型**——
> 名片码给 3 分，Wi-Fi 码也给 3 分，因为扫码就能连进人家的网。

---

### 2:00–2:40　案例三：看不见的隐私

**操作**：点「快递面单 · 带拍摄信息」。

（右栏"发现项"上方多一行灰字："另有 4 条拍摄信息（GPS／时间／机型等），不出现在清单里——它们始终整图清除"）

**口播**：

> 前面两个是"看得见"的。真正容易漏的是看不见的：
> 这张图里带着 GPS 坐标、拍摄时间、机型、处理软件。
> 你发原图，等于把**拍摄地点**一起发出去了。
> 这些不出现在勾选列表里，因为**它们始终整图清除**，不需要你决定。

**要点**："不需要你决定" = 减少用户负担，是产品判断。

---

### 2:40–3:00　留白：取消勾选也是决定

**操作**：把其中一个号码的勾去掉。

（那个框从实线彩色变成灰色虚线）

**口播**：

> 如果我这一块不想擦——比如这是公司的公开电话——取消勾选，
> 它就变成灰的。**"保留"也是一个明确决定，不是漏掉。**
> 后面报告里会写清"擦 2 项、留 1 项"。

---

### 3:00–3:30　手动补框：检测漏了怎么办

**操作**：点「手动补框」→ 在图上空白处拖一个矩形。

（紫色虚线框）

**口播**：

> 检测一定会漏——手写、艺术字、被遮住的都会有。
> 所以留了个兜底：手动拖一个框，它按同样的规则参与处置和复检。
> **承认会漏，并给用户补救手段**，比宣称 100% 检出更实在。

---

### 3:30–4:10　生成 + 对比 + 报告

**操作**：点「生成脱敏副本」→ 等 5–10 秒 → 自动切到「对比」→ 拖动滑杆。

（左边原图、右边处理后；滑杆拖过号码时号码消失）

**口播**：

> 现在是处理后的。拖一下能看到差别——号码没了，其他内容一点没动。
> 下面这份是**复检报告**：
> 计划区域 3 个、逐区域回读 3 项全部通过、残留 0、**整图重扫新增 0**。
> 最后一行是关键：原图的 SHA-256 没变，**我只生成了副本，没动你的原图**。

**要点**：强调"整图重扫"——只验遮盖区是不够的，框外可能还有残留。

---

### 4:10–4:40　三态：为什么有"待确认"

**操作**：如果刚才加过手动框，报告状态会是「部分待确认」（黄）。
（若没加，可口头说明）

**口播**：

> 注意这里可能是黄色"部分待确认"，而不是绿色"通过"。
> 因为我手动加的那块，**程序没法判断它原来是什么内容**，
> 只能确认"这块被盖住了"，不能确认"这块原本没有隐私"。
> 我不把它写成通过——**报告可以说"没发现"，但不能说"安全"**。

---

### 4:40–5:00　上传自己的照片 + 收尾

**操作**：点「上传照片」，选一张自己的照片。

（2–5 秒出结果，可能 0 条，也可能有手机号）

**口播**：

> 换一张没见过的照片也行。它只在本机跑，所以我可以放心拿自己的照片试。
>
> 最后说一句边界：合成数据上我的召回是 100%，但**实拍的 14 张只有 84.6%**，
> 二维码在屏幕翻拍下是 0——因为摩尔纹让码解不出来，不是算法没写。
> 这两个数字我都会写在报告里，不会只报第一个。

**要点**：主动交代短板，收尾最加分。

---

## 三、如果时间只剩 2 分钟

只走三步：**案例一（0:30）→ 生成与报告（3:30）→ 边界（4:40）**。
其余跳过，一句话带过。

## 四、可能被打断的问题（一句话版）

| 问题        | 一句话                                                                       |
| --------- | ------------------------------------------------------------------------- |
| 用什么模型？    | OCR 是 RapidOCR（ONNX），人脸 MediaPipe，二维码是 OpenCV + pyzbar 双后端，号码是规则 + 国际校验算法 |
| 为什么不用大模型？ | 隐私数据不该出本机；而且号码判定是可解释的硬规则，大模型反而会编                                          |
| 准确率？      | 合成集 100%，实拍手机号 84.6%、身份证 66.7%、误报 0；样本量小，我在报告里标了区间                        |
| 怎么保证擦干净？  | 擦完把每块单独再读一遍，再做整图重扫，元数据用 ExifTool 独立复核                                     |
| 这是你一个人做的？ | 检测引擎和处置后端是两位队友写的，我做契约、数据、评测、界面和集成；三方靠一份 JSON Schema 对齐                    |
| 最难的地方？    | 不是检测，是让三个人对同一个字段的理解一致——最后靠 schema + 校验器钉死                                 |

## 五、故障预案

| 现象            | 处理                                              |
| ------------- | ----------------------------------------------- |
| 双击没反应 / 闪一下就关 | 双击 `自检.bat`，把输出给面试官看："它自己会诊断"——**这反而是加分项**      |
| 浏览器没自动打开      | 手动访问命令行里打印的地址（端口会自动顺延，别照抄 7861）                 |
| 检测很慢（>10 秒）   | 说"第一次要加载模型"，同时点第二个示例；后续会快                       |
| 报错弹红条         | 念出错误信息，说"这是我留的显式报错，不是静默失败"，然后换一张示例              |
| 杀毒软件拦截        | 提前把 `runtime\python.exe` 加信任；现场被拦就说"便携解释器常见的误报" |
| 演示机没有 D 盘     | 解压到任何**不含中文、有写权限**的目录均可                         |

---

## 六、演示后的收尾动作

- 关掉命令行窗口（程序退出）
- 如需清理：删掉 `PhotoCheck_App\work\` 即可（演示中处理过的图片都在里面）
