# 本地服务信任边界加固（2026-11-22）

## 结论

仅绑定 `127.0.0.1` 只能限制“哪个网络接口可访问”，不能限制“哪个网页可以调用”。
浏览器中的任意站点都能尝试请求本机端口，DNS rebinding 还可能让攻击者域名解析到
本机地址。本轮在应用 HTTP 层增加三道校验。

## 校验

1. **Host 白名单**：只接受 `127.0.0.1:<实际端口>`、`localhost:<实际端口>`，
   IPv6 监听时增加 `[::1]:<实际端口>`。
2. **Sec-Fetch-Site**：拒绝 `cross-site` 与 `same-site`。
3. **Origin 白名单**：没有 `Sec-Fetch-*` 的旧浏览器，外来 Origin 同样返回 403。

每个 server 实例使用独立派生 Handler，白名单按真实端口生成；`port=0` 和多个
server 并存时不会互相覆盖。

## 验证

`app/tests/test_server_trust.py` 的 8 条测试和原有并发 429 测试均通过：

```text
9 passed
```

覆盖正常请求、DNS rebinding Host、cross-site、same-site、外来 Origin、同源请求、
POST 请求以及两个 server 白名单隔离。

## 边界

- 这不是用户认证机制，应用仍假定同一名本机用户操作。
- 不改变“不联网”承诺；服务仍只监听本机回环地址。
- 不在日志中记录被拒绝请求的敏感正文。
