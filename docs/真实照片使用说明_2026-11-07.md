# 真实照片使用说明

> 面向：需要决定"要不要提供照片、提供什么、怎么给"的人
> 日期：2026-11-07 ｜ 对应代码：`dataset/real/` + `tools/real_samples_check.py`

## 一、现在是什么情况

C 的 43 张测试图**全部是程序画的**，一张实拍都没有。这带来三个绕不过去的偏差：

| 偏差 | 具体表现 | 后果 |
|---|---|---|
| 没有拍摄角度 | 全是正视，无倾斜、无透视变形 | 真实照片斜着拍，文字会被拉伸，OCR 可能认不出 |
| 文字过于清晰 | 无手抖、无低光噪点、无纸张褶皱、无阴影 | 真实翻拍的信噪比低得多 |
| 不含人脸 | 无合规来源，K-07 一条样本都没有 | 人脸检测**从来没被验证过** |

所以报告里那句"召回 100%"，准确说法是：**在 43 张合成图上召回 100%**。

答辩或评审只要问一句"真实照片也这样吗"，现在**答不上来**——因为没测过。

## 二、照片要用来做什么

先澄清一件容易误会的事：**不是拿去训练模型**。

这个项目不训练任何模型（不允许联网、不允许下载权重），检测靠的是规则 + 预训练好的现成模型。照片只用于**验证**，具体三件事：

| 用途 | 做什么 | 产出 |
|---|---|---|
| **验泛化** | 拿真照片跑一遍检测器，看召回从 100% 掉到多少 | 报告里"真实样本"独立一节 |
| **验流程** | 真实照片动辄 3000×4000，看界面会不会卡、会不会超时 | 性能结论 |
| **补人脸** | 有授权正脸照才能验 K-07 | 人脸召回（可选） |

**照片不做什么**：

- 不进 dev 集，不和合成集混算平均值（混算等于用干净数据稀释真实难度，得出一个谁都不信的中间值）
- 不用于调参（调参要用 dev，真实照片只做最终验证）
- 不用于训练

## 三、会不会泄露

分三条传播路径看，**两条安全、一条有风险**。

### 路径 1：git 版本历史 —— **不会**

`dataset/real/` 已经写进 `.gitignore`：

```gitignore
# 授权真实照片可能带使用限制，不入库（只在本地放着，靠 manifest 记账）
dataset/real/
dataset/**/real/
```

放在这个目录的照片**不会**被 `git add` 收进去，也就不会留在历史里。

> 为什么强调"历史"：文件删了但提交过，`git log` 里还能翻出来。这是很多人以为"删了就没事"的坑。

### 路径 2：交付包（发给 A 和 B 的 zip）—— **不会**

`tools/make_handoff.py` 打包用的是 `git ls-files`，只收**已跟踪**的文件。gitignore 的东西进不去。

已验证：当前两个交付包里 `dataset/` 下是 43 张合成图，没有任何 `real/` 内容。

### 路径 3：截图、录屏、发群、发邮件 —— **会，这是唯一真实的风险**

代码拦不住这个。你截一张界面图发到群里，照片里的一切就出去了。

**而且有个更隐蔽的点**：这个工具的界面会**用框标出敏感内容的位置**。截图发出去，等于把"哪块是手机号、哪块是身份证"直接指给看的人。

## 四、隐私风险具体是什么

| 风险 | 说明 | 严重度 |
|---|---|---|
| **照片本身含真实 PII** | 拍真快递单 → 上面是别人的真手机号、真地址 | 高 |
| **界面截图暴露敏感位置** | 检测框会高亮"这块是身份证"，截图等于做标注 | 中 |
| **原图留在硬盘** | 掩码只保护"导出的副本"，原图还在 `dataset/real/` 里 | 低（但要知道） |
| **肖像权** | 拍别人的脸 → 即使"他说可以"，书面授权缺失仍然是隐患 | 高 |

## 五、保护措施（三层）

### 第 1 层：拍的时候就规避（最有效）

| 做法 | 为什么 |
|---|---|
| **内容虚构**：号码自己编、姓名用"张三"、二维码生成个假的 | 你测的是"检测器能不能认出它长得像敏感信息"，不是"能不能读到真隐私" |
| **只拍自己的东西** | 自己的东西自己授权，最干净 |
| **不拍真证件、真发票、真快递单** | 这些上面的信息属于别人 |
| **优先"屏幕翻拍"**：把合成图显示在屏幕上，用手机拍屏幕 | 介于合成和实拍之间，有角度有反光有摩尔纹，但内容 100% 虚构——**性价比最高** |

### 第 2 层：存放与防误提交

| 措施 | 落地方式 |
|---|---|
| 目录被 gitignore | `dataset/real/`，已验证 |
| 防 `git add -f` 手滑 | `python tools/real_samples_check.py` 会检查并报警 |
| 授权可追溯 | `manifest.csv` 的 `consent` 列必填 |

### 第 3 层：使用与传播

| 措施 | 做法 |
|---|---|
| 截图只截**掩码后**的界面 | 掩码后的图看不出原信息 |
| 不把原图贴进任何文档/PPT | 报告里引用**文件哈希**，不引用图片 |
| 用完可删 | 删前跑 `--seal` 记哈希，报告引用哈希即可 |

## 六、需要你提供什么材料

### 必需（缺了这条就补不上）

| # | 材料 | 数量 | 具体要求 |
|---|---|---|---|
| 1 | **虚构内容的实拍照片** | **8–12 张** | 手机拍、内容自己编、有角度有反光；覆盖单据/名片/通知三类 |
| 2 | **`manifest.csv`** | 1 份 | 从 `manifest.example.csv` 复制填写，每张一行 |
| 3 | **授权说明** | 1 份 | 一页纸，写清"谁拍的、什么时候、同意用于本项目验证" |

### 可选（建议先不做）

| # | 材料 | 数量 | 说明 |
|---|---|---|---|
| 4 | 本人正脸照 | 3–5 张 | **只补 K-07**。风险最高（肖像权），且没有真人脸也不阻塞主线——现在 K-07 就是 `not_applicable` |
| 5 | 团队成员授权书 | 每人 1 份 | 如果要用队友的脸/物品，必须有签字 |

### 明确不需要

- ❌ 真实身份证、真实发票、真实快递单
- ❌ 真实聊天记录截图
- ❌ 别人的照片，哪怕对方口头同意

### 一张照片的最低要求

```
✅ 能看清内容（不用艺术摄影）
✅ 有轻微角度（不要完全正视，也别太斜到认不出）
✅ 内容是自己编的
✅ manifest 里能说清来源
```

**不需要**：专业相机、打光、后期处理。要的就是"随手拍"的那种不完美。

## 七、逐步操作流程

### 第 0 步：确认目录在（30 秒）

```bash
cd D:\PhotoCheck
ls dataset/real
```

应该看到 `README.md` 和 `manifest.example.csv`。

**如果没有**：说明目录被删了，重建：

```bash
mkdir -p dataset/real
```

> `dataset/real/` 已在 `.gitignore` 里，所以空目录不会出现在 git 里。这是正常的。

### 第 1 步：拍照片（约 30 分钟）

用手机拍，建议按这个清单凑够 8–12 张：

| 场景 | 张数 | 内容建议 |
|---|---|---|
| 快递面单 | 3 | 手写/打印的虚构号码，收件人写"张三" |
| 名片 | 2 | 虚构公司、虚构电话 |
| 通知/登记表 | 2 | 虚构姓名、虚构身份证号 |
| 带二维码的纸 | 2 | 用手机生成一个假二维码（比如"测试用"文本）印出来或显示在另一个屏幕上 |
| 屏幕翻拍 | 2 | 把 `dataset/dev/images/` 里的合成图显示在电脑上，用手机拍屏幕 |

**拍摄要点**：

- 稍微斜一点（8–15 度），别完全平视
- 光线不要太完美，室内日光灯就行
- 允许有反光、有阴影、纸有点皱
- **不要**刻意模糊到看不清

### 第 2 步：放进目录（2 分钟）

```bash
# 命名从 real-001.jpg 起，连续编号
copy 你的照片\IMG_1234.jpg dataset\real\real-001.jpg
```

**命名规则**：`real-001.jpg`、`real-002.jpg`……**不要用手机默认名**（`IMG_1234.jpg` 看不出顺序，也没法对应 manifest）。

### 第 3 步：填 manifest（10 分钟）

```bash
copy dataset\real\manifest.example.csv dataset\real\manifest.csv
```

然后用记事本/Excel 打开 `manifest.csv`，每张照片一行：

```csv
file,consent,shot_with,angle,glare,light,objects,note
real-001.jpg,self,手机后置,轻微倾斜 8°,无,室内日光灯,phone=1;qr=1,仿快递面单；号码编的
real-002.jpg,self,手机后置,俯拍 15°,左上反光,窗边逆光,phone=1,仿名片；姓名虚构
```

| 列 | 填什么 |
|---|---|
| `file` | 文件名，必须和实际一致 |
| `consent` | `self` / `team-written` / `synthetic-photo`，**必填** |
| `shot_with` | 什么设备拍的 |
| `angle` | 大致角度，写"正视"也行 |
| `glare` | 有没有反光 |
| `light` | 光照条件 |
| `objects` | 图里有几个敏感对象，人工数（如 `phone=2;idcard=1`） |
| `note` | 一句话说明 |

**`objects` 这列很关键**：它是唯一的人工真值。没有它，就没法算"检出率"。

### 第 4 步：跑检查（1 分钟）

```bash
python tools/real_samples_check.py
```

正常输出应该像这样：

```
[OK] 没有照片被 git 跟踪

共 10 条记录：
  文件               授权           尺寸         对象                 状态
  ------------------------------------------------------------------------------
  real-001.jpg       self          3024×4032    phone=1;qr=1         OK
  real-002.jpg       self          3024×4032    phone=1              OK

全部通过。真实照片不进 git、授权齐全、文件可读。
```

**如果报"照片已被 git 跟踪"**：说明有人 `git add -f` 过，立刻处理：

```bash
git rm --cached dataset/real/real-001.jpg
```

### 第 5 步：用起来（我这边做）

照片就位后告诉我，我会：

1. 用 A 的检测器跑一遍，逐张对照 `objects` 列算检出率
2. 记录每张的耗时（真实大图通常比合成图慢）
3. 输出"合成 vs 真实"对照表，**两个数字分开列，不混算**
4. 写进报告"真实样本验证"一节

### 第 6 步：收尾（可选）

照片可以留在本地，也可以删。**删之前先记哈希**：

```bash
python tools/real_samples_check.py --seal
```

生成 `dataset/real/SEALED.json`，里面有每张图的 SHA-256。报告引用哈希即可证明"确实测过这批图"，不必保留图片。

## 八、几个常见问题

**Q：一定要实拍吗？能不能用网上的图？**
不能。网上的图来源不明、授权不清，而且大概率带真实 PII。要么自己拍，要么翻拍自己的合成图。

**Q：屏幕翻拍算不算"真实照片"？**
算一半。它有角度、反光、摩尔纹、屏幕像素纹，这些是合成图没有的；但内容仍是 100% 虚构。**这是性价比最高的方案**——10 分钟能凑 5 张，零隐私风险。建议先做这个。

**Q：一张都不想拍行不行？**
行。那就在报告里如实写"仅合成数据验证，未覆盖拍摄角度/反光/低光，泛化性未验证"。**诚实描述限制，比伪造真实性安全得多。**

**Q：人脸那部分必须拍吗？**
不建议。人脸的风险（肖像权）远高于收益（补一个 P1 卡的召回率）。保持 `not_applicable` 并在报告里写明原因，是更负责的做法。

**Q：照片拍糊了/太暗怎么办？**
留着。**这正是要测的东西**——真实照片就是不完美的。如果检测器在糊图上漏了，那是有价值的发现，不是失败。

## 九、一句话总结

**要的是"有瑕疵的虚构照片"，不是"漂亮的真实证件"。**

内容编的、随手拍的、有角度有反光的——这种照片既能验证泛化，又不带来任何隐私负担。
