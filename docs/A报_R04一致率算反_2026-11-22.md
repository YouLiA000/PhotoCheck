## 一、现象

两份评审表都填 `not_readable`（30/30），机器的 `primary_status` 与 `tesseract_status` 也都是 `passed`（30/30）。
也就是说：**人看读不出、机器判无残留，两边结论完全一致。**

但 `manual-summary.json` 输出：

```json
{
  "sample_size": 30,
  "reviewer_agreement_rate": 1.0,
  "cohen_kappa": 1.0,
  "human_not_readable": 30,
  "primary_vs_human_agreement": 0.0,
  "tesseract_vs_human_agreement": 0.0,
  "manual_review_status": "complete_two_independent_reviewers"
}
```

前三项对，后两项**正好相反**。

## 二、根因：两个变量极性相反

```python
# tools/finalize_r04_manual.py:57-61
human_values = [
    1 if str(row["manual_consensus"]).lower() == "readable" else 0   # 1 = 还能读出（坏）
    for row in rows
]
primary_values = [int(row.get("primary_status") == "passed") for row in rows]     # 1 = 无残留（好）
tesseract_values = [int(row.get("tesseract_status") == "passed") for row in rows] # 同上

# :69-76
"primary_vs_human_agreement": round(
    sum(a == b for a, b in zip(primary_values, human_values)) / len(rows), 4
),
```

`human` 的 1 表示"失败"，`primary` 的 1 表示"成功"。用 `==` 比较，等于在数"两边**不一样**的比例"。

实测：

```
全部 30 行：human = 0（not_readable）、primary = 1（passed）
sum(a == b) / 30 = 0.0     ← 脚本现在报的
sum(a != b) / 30 = 1.0     ← 语义上正确的一致率
tesseract 同理：0.0 → 1.0
```

## 三、为什么这条比"数字难看"严重

1. 报告会写「人工与机器一致率 0%」，而事实是 100%。审计看到 0% 会判 R-04 失败。
2. 更坏的情况：有人看到 0% 以为是评审填反了，去翻 `human` 标签——
   一翻，`human_readable` 变成 30，真正的结论也被翻掉，而且看起来"数字终于对了"。
3. 这类 bug 不报错、不崩，只是静静给出反向结论——和之前几个"绿勾掩盖缺失"是同一族。

## 四、建议

**改法（一行）**：

```python
"primary_vs_human_agreement": round(
    sum(a != b for a, b in zip(primary_values, human_values)) / len(rows), 4
),
```

或者把 `human_values` 改成同一极性（`1 if == "not_readable"`）再比 `==`，但前者更不容易再写错。

**补测试**（比改代码重要）：

```python
def test_agreement_is_not_inverted():
    rows = [{"manual_consensus": "not_readable", "primary_status": "passed",
             "tesseract_status": "passed"}] * 30
    summary = ...  # 调统计函数
    assert summary["primary_vs_human_agreement"] == 1.0
    assert summary["tesseract_vs_human_agreement"] == 1.0
```

现在这个文件**没有任何测试**，所以 30 行全 `not_readable` 这种最常见的情形也没被覆盖过。

## 五、附带一条：`manual_review_status` 是硬编码

```python
# :77
"manual_review_status": "complete_two_independent_reviewers",
```

字面量。只在前面"行数、取值合法性"校验都过了才会走到这行，所以语义上不算错——
但它**不是**独立校验：它证明的是"表填满了且值合法"，不是"两个人真的独立填的"。
审计若把 `manual_review_status` 当作独立性证据，强度不足；独立性只能靠流程保证
（两份隔离表 + 不互传 + 各自签名），这一点现在的表单设计是对的，别在脚本里假装它。

## 七、修复记录（2026-11-22 13:45）

### 7.1 改了什么

只改 `tools/finalize_r04_manual.py` 的三行取值与两行比较，**没有动任何判定逻辑、字段名或输出结构**：

```python
# 统一成"是否仍有残留"这一个极性，== 才读得通
human_residual     = [str(row["manual_consensus"]).lower() == "readable" for row in rows]
primary_residual   = [row.get("primary_status") != "passed" for row in rows]
tesseract_residual = [row.get("tesseract_status") != "passed" for row in rows]

"primary_vs_human_agreement": round(
    sum(a == b for a, b in zip(primary_residual, human_residual)) / len(rows), 4),
"tesseract_vs_human_agreement": round(
    sum(a == b for a, b in zip(tesseract_residual, human_residual)) / len(rows), 4),
```

选"把两个数组都翻成同一极性"而不是"把 `==` 改成 `!=`"，是因为后者虽然也对，
但下次有人读代码时仍然要停下来想一句"为什么一致率用不等于"——错就会再犯一次。
