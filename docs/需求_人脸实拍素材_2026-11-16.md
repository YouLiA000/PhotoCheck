# 需求：人脸实拍素材（2026-11-16）

> **口径来源**：`dataset/real/faces/README.md`（项目既有规范）。本文不改规范，只把**缺口量化**并给出补拍建议。
> **目标**：K-07 授权人脸样本 **20 张**，一图一可见脸。

---

## 一、既有规则（先明确，避免另立一套）

1. 目标 **20 张**；不足时必须**如实报缺口**，不得用公开数据集、AI 生成脸或重复图片凑数。
2. **一图一可见脸**——`truth_faces = 1`。多人同框**不能**进这个集。
3. 朝向矫正可用 0 / 90 / 180 / 270（可用检测器辅助判断），但真值仍是「一张脸」。
4. 源图、`manifest.local.csv`、`summary.local.json` **一律不入 Git**；只提交统计与本 README。
5. 每张源图需**逐张授权**，记录留在 Git 外。

## 三、这 16 张怎么拍才不浪费

只要满足「一图一可见脸」即可，但**必须覆盖失败模式**，否则集齐 20 张也说明不了问题：

| 建议 | 张数 | 理由 |
|---|---:|---|
| 正脸、50cm 与 1.5m 各半 | 8 | 基线检出率。现有正脸只有 1 张，下不了结论 |
| 侧脸 30° / 45° / 90° | 4 | #2 已证明会漏检，要摸到角度临界点 |
| 遮挡：口罩 / 手挡半脸 / 墨镜 | 3 | 口罩是日常最普遍场景 |
| 逆光 1、暗光 1 | 1~2 | 逆光下人脸成剪影，典型失败模式 |
| **合计** | **16** | |

**至少 3 个不同的人**。同一人多角度再多，也只能证明「对这个人有效」。

> 想测「多人同框」「海报人脸误报」的话，**另开 `dataset/real/face_probe/`**，
> 不要混进 K-07 集——那会破坏「一图一脸」的真值口径，审计也难以复核。

## 四、交付方式（用既有工具，不要手工建 manifest）

把 16 张源图放进一个目录，然后：

```powershell
python tools\prepare_face_samples.py --source "<源图目录>"
```

会生成 `images/`、`manifest.local.csv`、`summary.local.json`。
验收看 `summary.local.json` 的 `complete_required_count` 是否为 `true`。

---

## 五、三个必须注意

1. **用手机原生相机拍，数据线拷**。微信「原图」仍可能剥 EXIF；这批本来可以用来顺带验证元数据清理，别浪费。
2. **#3 那张不能进集**——不是「质量差」，是 `truth_faces` 记不了 1，会让统计口径失真。
3. **授权**：每位出镜者录一句「同意用于 PhotoCheck 检测测试」，写在 `dataset/real/face_probe/CONSENT.md`（或同位置），不入库。

---

## 六、验收判据

| 项 | 判据 |
|---|---|
| 数量 | `summary.local.json` 里 `complete_required_count == true`（≥20） |
| 真值 | 每行 `truth_faces = 1`，且 `detected_faces` 与实际检出一致 |
| 条件分布 | `frontal_or_near_frontal` 与 `profile_or_partial` 都有，不能全是正脸 |
| 授权 | 每行 `authorization` 非空 |
| 入库 | `images/` 与 `manifest.local.csv` **不在** `git status` 里 |

结论只允许两种写法：**「当前 X/Y 张检出，角度 ≤N° 可检出」** 或 **「样本不足，K-07 未完成」**。
不允许写「人脸检测效果良好」。

## 七、不外泄：技术保障与人工纪律

这批照片是**参与者自愿提供**的，前提是「只在本机、不上传云端、不外泄」。以下不是承诺，是可验证的机制。

### 已经有机器兜底的四层

| 层 | 做法 | 怎么验证 |
|---|---|---|
| Git 忽略 | `dataset/real/*` 全部忽略，只放行 4 个说明/示例文件；`work/`（应用上传副本）、`results/`、`dist/` 同样忽略 | `git check-ignore` 逐条验过，9 条敏感路径全部命中 |
| 索引守卫 | `dataset/tools/tests/test_real_photos_local_only.py` 三条断言：① 索引里不得有任何照片或本地清单；② 代表性路径必须仍被忽略；③ 说明文件不得被一并忽略 | **已用 `git add -f` 故意造一次违规，测试确实变红**；清理后回到绿 |
| 当前状态 | `git ls-files dataset/real` 只有 4 个 md/csv，**一张照片都没有** | 可随时复查 |
| 打包隔离 | `tools/build_app.py` 只打包 `app/`，不碰 `dataset/` | 读脚本可得 |

### 技术拦不住、必须靠人的三件事

1. **别把 `D:\PhotoCheck` 放进同步盘**（OneDrive / 坚果云 / Dropbox）。Git 忽略管不到网盘的同步。
2. **别把照片发给别人**，包括「帮我看看这张能不能认出来」——这就是外泄。
3. **截图、录屏、AI 助手的图片缓存都会留副本**。用完即清。

### 万一照片进过 Git

`git rm --cached` **不够**。只要进过提交并被推送，就必须按「已外泄」处理：
重写历史、强推、并逐个通知出镜人。守卫测试存在的意义就是让这一步不发生。
