## 二、一维条码：证据（回应 C 第 4 节）

`qr_backend=pyzbar` 只证明后端能加载。为证明"真的能识别"，新增
`scripts/verify_barcode.py`，一次产出图 + 记录 + JSON：

| 用例 | 内容 | 结果 |
|---|---|---|
| `ean13_good` | EAN-13 `6901234567892`（95 模块 / 4px 每模块 / 带静区） | **1 条 `qr_code` / risk 1 / bbox [120, 70, 380, 119]** |
| `ean13_badcheck` | 视觉几乎相同，校验位故意错 | **0 条** |
| `stripes` | 装饰竖条纹，同一节奏但无起始/终止符 | **0 条** |

产物：`reports/barcode_evidence/`（3 张 PNG + `results.json`）。复跑：

```bash
python scripts/verify_barcode.py                                      # 本机需 pyzbar 可加载
python scripts/verify_barcode.py --fix-crt "<含 MSVCR120.dll 的目录>"   # 主机缺运行库时的验证绕行
```

**重要区分**（C 指出的点，A 接受）：

- **故障是 A 主机的**：缺 64 位 `MSVCR120.dll`（VS2013 运行库）。B 环境实测 `qr_backend=pyzbar` 正常。
- **`--fix-crt` 是验证手段，不是产品依赖**。产品代码不做注入，pyzbar 不可用时如实上报 `qr_backend=cv2`。
- 结论：**一维条码代码路径可用，且已在本机验证通过**；正式环境依赖 VS2013 x64 运行库（B 的环境本来就有）。
