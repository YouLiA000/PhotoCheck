## 3. 问题 1（实质缺陷）：导出图整图重扫仍报 1 个 `qr_unknown`

**现象**：对导出文件跑一次完整 `analyze()`，仍得到 1 条检测：

```
det-qr-001  qr  qr_unknown  bbox=[152, 194, 322, 290]  details={'decodable': False}
```

裁图（`reports/b_verify_20261106/export_residual_fp_box.png`）确认：**这个框里没有任何二维码**，
是「李小雁 / 某某大学 3 号宿舍楼 / 8-2-1123」这块文字区。

**为什么你的复检没发现**：`core/verification.py` 的 checks 是
`for region in redacted.applied_regions` —— 只探"计划的遮盖区域"，框外的残留不看。
所以区域内确实干净（我复算也是 0/0），但"整图还有一条 QR"这件事被跳过了。

**根因（是我这边的问题）**：我的 `detect_qr()` 在 pyzbar 一个都没解出时会兜底跑
`cv2.QRCodeDetector.detectMulti()`，它会在文字密集区吐出候选四边形，而"解不出也报框"
的策略没有对候选加证据要求 → 变成 `qr_unknown` 误报。这正是 C 在 11-06 报告里写的 7 条误报，
我在你这个包上独立复现到了同一条。

**重要**：这条的 `w/h = 322/290 = 1.11`，**落在 C 建议的 `0.75~1.35` 里**。
也就是说 C 的方案 1（长宽比过滤）挡不住它，必须上方案 2（要求定位符 finder pattern 证据）。
这条已记入我的待修清单，修完会拿这张导出图当验收样本：**整图重扫必须 0 条**。

**给你的建议**（等我的修复合入后再加）：
在 K-09 里加一步"导出后整图重扫"，要求 `analyze(output).detections == []`。
现在加会误杀——因为上面的误报还在。顺序不能反。

## 5. 问题 3（环境）：ExifTool 不在包里，缺了会error 而不是 skip

按清单 §5.4 我先装 ExifTool 才跑；**装之前 `photocheck\tests` 是 `50 tests / 18 errors`**，
18 条全是 `MetadataScanError: ExifTool not found`，覆盖 k01 / k02 / pre_detection /
content_verification / a_contract_alignment 五个文件。

`ingest_image()` 直接把 `MetadataScanError` 包成 `ImageIngestError` 抛出，所以：
- 任何没装 ExifTool 的机器，B 的主流程整条走不通（不只是测试）；
- 这属于**外部程序依赖**，清单里只写在 §5.4 的安装步骤，没写"缺了会怎样"。

建议二选一：把它写进 `README` 的前置条件并在缺省时给出可执行提示；
或让 ingest 在"只做检测、不做导出"的场景下降级并进 warnings（导出仍必须要求它）。
另外建议钉版本（我用的 13.61），不同版本的 tag 输出差异会影响 `metadata_residual_tags()`。
