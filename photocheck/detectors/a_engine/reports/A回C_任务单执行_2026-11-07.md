### A-3｜BC-0008 —— 根因已定位，结论和你的两条判断都不同

**(1) `detector_status()` 报的是 `cv2`，是准的**

```
{'ocr': 'ok', 'qr': 'ok', 'face': 'ok', 'qr_backend': 'cv2'}
```

**(2) 根因：缺 64 位 `MSVCR120.dll`**

`libzbar-64.dll` 的导入表：

```
KERNEL32.dll  USER32.dll  WINMM.dll  MSVCR120.dll  libiconv.dll  libzbar64-0.dll
```

本机 `C:\Windows\System32\MSVCR120.dll` **不存在**；`SysWOW64` 里那份是 32 位，64 位进程用不上。
所以报错是"找不到模块 xxx.dll（或它的某个依赖）"——**文件明明在**，缺的是它依赖的 CRT。

验证（不改代码、不重装任何包，只把一份 64 位 CRT 目录加进 DLL 搜索路径）：

```python
os.add_dll_directory(r"C:\Program Files\Microsoft Office\root\Client")  # 那里有 64 位 msvcr120.dll
ctypes.CDLL(r"...\pyzbar\libzbar-64.dll")   # 原来 OSError，加了之后成功
```

我之前在 BC-0008 里写"已排除 MSVC 运行时齐全"，那是误判：查的是 `vcruntime140`（VS2015+），
而 libzbar 要的是 `MSVCR120`（VS2013）。两者不是一回事，这条已在坏例里更正。

### A-4｜BC-0005 `+86` —— 已实现、已验，请转 fixed

实现形态：`(?<!\d)(?:(?:\+86|0086)1[3-9]\d{9}|1[3-9]\d{9})(?!\d)`，匹配前按规格卡去掉空格/短横/全角。

已验四件事：

| 项 | 结果 |
|---|---|
| `<PHONE-INTL-A>` / `<PHONE-INTL-B>` / `<PHONE-INTL-C>` | 各识别为 1 个号码 |
| 匹配区间 | **从区号第一个字符开始**（`start == 0`），到末位数字结束 |
| 遮盖框 | 含区号；否则号码看着被遮了，实际还能拨 |
| 掩码 | 先剥区号再掩码 → `138****8000`（剥之前掩会把区号露在外、把号段藏起来，是反的） |

请 C 造样本时用上面这**三种形态**（带空格、带短横、`0086`），不要只造紧邻的 `+8613...`。
另外注意：剥前缀后**仍按 11 位校验**，不会把 `+86` 后面 13 位整体当号码。
